# Panels

Panels hold what sits next to the pages: thumbnails, the outline, search results, comments. Each
one has a button, `panel:<id>`, and a side. Move one with `panel(id, changes)`:

```js
{
  layout: (layout) => layout.panel('thumbnails', { side: 'end' }),
}
```

## The built-in panels

| Panel | What's in it | Side | Opens with |
| :-- | :-- | :-- | :-- |
| `thumbnails` | A small picture of every page; pick one to go there, or [organize the pages](#organize-pages) | `start` | `panel:thumbnails` |
| `outline` | The document's table of contents (its bookmarks): follow, filter, and with the right to change the outline, add, rename, drag and delete items | `start` | `panel:outline` |
| `attachments` | Files inside the PDF | `start` | `panel:attachments` |
| `search` | Find text, and every match in context | `end` | `panel:search`, `search:find` (`Ctrl`/`Cmd`+`F`) |
| `comments` | Every comment and its replies | `end` | `panel:comments` |
| `style` | Color, width and font of the selected annotation, or of the tool | `end` | `panel:style` |
| `stamps` | Stamp libraries; pick one, then click the page | `end` | `panel:stamps` |
| `signatures` | Saved signatures and initials; the document's signatures | `end` | `panel:signatures` |
| `redaction` | Marked areas waiting to be removed | `end` | `panel:redaction` |
| `measurement` | The scale, and every measurement on the page | `end` | `panel:measurement` |
| `form-design` | The form's fields, and the selected one's settings and buttons; in the Form mode only | `end` | `form:design`, `panel:form-design` |

A panel whose feature you [turn off](../features/turning-off) is gone, with its button.

## How a panel opens

A panel opens in one of three ways:

| `present` | What it does |
| :-- | :-- |
| `'dock'` | Beside the pages, which make room for it |
| `'overlay'` | Over the edge of the pages, which stay where they are and dim; a click on them closes it. The toolbars keep working. |
| `'sheet'` | Up from the bottom of the viewer, over everything |

By default a panel is a sheet on a phone, an overlay at medium widths, and docks when the viewer
is wide: `{ compact: 'sheet', medium: 'overlay', expanded: 'dock' }`. Give `present` one way for
every size, or a way for the sizes you name; the other sizes keep the default:

```js
{
  layout: (layout) =>
    layout
      // Every panel docks at medium widths too: never an overlay.
      .panels({ present: { medium: 'dock' } })
      // The thumbnails open over the pages on a phone, not as a sheet.
      .panel('thumbnails', { present: { compact: 'overlay' } })
      // The comments always open over the pages.
      .panel('comments', { present: 'overlay' }),
}
```

`panels(changes)` changes every panel the layout has so far, the way `panel(id, changes)` changes
one. A map of sizes changes only the sizes it names, so the thumbnails above still dock at medium
widths. The sizes go by the viewer's own width: see [Small screens](small-screens#the-three-sizes).

## Width

A panel starts 288 px wide. People can drag its edge, or use the arrow keys on it, between 200 and
640 px and never past half the viewer, and the viewer keeps that width while it runs. Set where it
starts, how far it drags, or no dragging at all:

```js
layout.panel('comments', { width: 360 }); // where it starts
layout.panel('comments', { width: { initial: 360, min: 280, max: 520 } }); // and how far it drags
layout.panel('comments', { resizable: false }); // no edge to drag
```

`panels()` takes them too: `layout.panels({ resizable: false })` fixes every panel's width.

### Keep the width people chose

`onPanelResize` tells you each width someone gives a panel: once a drag ends, and on each arrow
key. Keep it where you like, and start the panel at it next time:

```js
const saved = Number(localStorage.getItem('thumbnails-width'));

{
  layout: (layout) => (saved ? layout.panel('thumbnails', { width: saved }) : layout),
  onPanelResize: ({ id, width }) => {
    if (id === 'thumbnails') localStorage.setItem('thumbnails-width', String(width));
  },
}
```

A number keeps the panel's limits: it only says where it starts. The `<embedpdf-viewer>` element
fires `epdf:panelresize` with the same `{ id, width }` as `event.detail`.

## The thumbnails

The thumbnails wrap: one column at the panel's default width, and more as it gets wider. They are
a second [Stage](/docs/headless/viewing/stage) over the same document, so `plugins.thumbnails`
takes the Stage's settings:

```js
{
  plugins: {
    thumbnails: {
      zoom: { pageWidth: 110 }, // each thumbnail 110 px wide; the default is 150
      columns: 1, // always one column; 'auto', the default, wraps
    },
  },
}
```

From code, `viewer.get('thumbnails')` is that Stage:
`viewer.get('thumbnails').updateSettings({ columns: 2 })`.

### Organize pages

Where the user may change the pages, the thumbnails panel is where they do it, as in most PDF
apps:

- **Select pages.** A click selects a page and goes to it; `Ctrl`/`Cmd`+click adds a page or
  takes it out, `Shift`+click selects a range.
- **The header** inserts a blank page, rotates and deletes the selected pages, and opens the menu
  of the rest; undo and redo sit at its end.
- **Each page has a menu**: its button, a right-click, or a long press. It rotates, inserts a
  blank page or a PDF after the page, duplicates, extracts and deletes.
- **Drag pages** to move them: a line shows where they land. Dragging a selected page moves the
  whole selection. On a phone, hold the page first, so a swipe still scrolls.
- **Drop a PDF** between two pages to insert its pages there, instead of opening it as a tab.
- **The keyboard**: the arrows go through the pages, `Shift` extends the selection, `Space` adds a
  page or takes it out, `Alt`+arrows move the selection one place, `Delete` deletes, and
  `Ctrl`/`Cmd`+`A` selects every page.

Every edit is one step of the history, so undo puts the pages back as they were, a deleted page
with its annotations. The buttons are the `page:*` [commands](commands), so `disable` and
`readOnly` turn editing off and leave a plain list of pages. A user without
`doc.pages.assemble` in their scope sees the plain list too.

## Panels on the same side

One panel shows per side at a time. Opening another on that side closes the first, and the panel's
header switches between the panels that share its side. Both sides can be open at once: the
thumbnails on the left and the comments on the right.

## Remove a panel

```js
layout.removePanel('attachments');
```

Its button goes with it, from every bar and menu.

## Open a panel from code

Run its command:

```js
viewer.commands.execute('panel:comments');
```

To open one with the cursor in it, ask the shell for focus:

```js
viewer.get('shell').open('search', { focus: true });
```

## Your own panel

Add it with `addPanel(id, panel)` and give the viewer what goes inside:

```js
layout.addPanel('notes', { side: 'end', title: 'Notes', icon: 'book' });
```

| Field | What it is | Default |
| :-- | :-- | :-- |
| `side` | `'start'` or `'end'` | `'end'` |
| `title` | Its title, in its header; or `titleKey` for a [translated](translations) one | none |
| `icon` | Its button's icon | none |
| `present` | `'dock'`, `'overlay'` or `'sheet'`, or one per size: `{ compact, medium, expanded }` | `{ compact: 'sheet', medium: 'overlay', expanded: 'dock' }` |
| `width` | Where it starts, in px, or `{ initial, min, max }` | `{ initial: 288, min: 200, max: 640 }` |
| `resizable` | Whether people can drag its edge | `true` |

The viewer draws the frame, the header and the way it opens; you draw what's inside. See [Your own
components](components#a-panel-of-your-own) for the content in each framework.

## Good to know

### Each document keeps its panels

With several documents open, each one remembers which panels were open, so switching tabs brings
them back. Widths are the viewer's: a panel keeps its width from one document to the next.

### Focus

An overlay or a sheet takes focus when it opens and gives it back to its button when it closes;
`Escape` closes it. A sheet keeps `Tab` inside it; from an overlay, `Tab` moves on to the
toolbars, which keep working while it's open. A docked panel takes focus only when it's asked
to: it's part of the page, and `Tab` reaches it in order.

Search asks, from its button and from `Ctrl`/`Cmd`+`F` (`search:find`): the cursor goes in its
field, with its text selected, so typing replaces it. `Ctrl`/`Cmd`+`F` works from any text field in
the viewer, the search field among them, and keeps search open. Your code asks with
`viewer.get('shell').open(id, { focus: true })`; a plain `open(id)` leaves the cursor where it is.
