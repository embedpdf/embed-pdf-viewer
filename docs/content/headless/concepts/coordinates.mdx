# Coordinates

Every position in EmbedPDF is in page space: points (1/72 inch) from the top-left corner of the
page as it's shown (its crop box), with y going down, like HTML. Annotations, text and search
matches, selections, reveal targets and overlays all use it. A box is `{ x, y, width, height }` and
a point is `{ x, y }`:

```ts
annotation.rect;
// { x: 100, y: 80, width: 20, height: 20 }
```

## Values pass straight through

Because every API speaks the same space, a value from one goes to another as it is. A comment
thread's root annotation is where the viewer should go:

```tsx
const threads = useCommentThreads();
const stage = useStage();

threads.map((t) => (
  <button
    key={annotationKey(t.root.ref)}
    onClick={() => stage.reveal(t.pageIndex, { rect: t.root.rect })}
  >
    {t.root.contents} — page {t.pageLabel}
  </button>
));
```

Calls that take a page address it by `PageRef` — `{ kind: 'objectNumber',
pageObjectNumber }`, the page's indirect object number, which survives reorder
and every edit. Records hand you one ready-made — `page.ref` on a page-list
entry, `page` on anything that points at a page (`dto.ref.page`, a search hit's
`hit.page`); `toPageRef(n)` builds one from a bare number.

## Pixels are never stored

Pixels change with every zoom, rotation, and scroll — so no EmbedPDF API
stores them. When you draw your own overlay, convert at the last moment:

```tsx
function Pin({ item, page }: AnnotationRendererProps) {
  // page space → this page's pixels (zoom + rotation handled)
  const px = page.transform.toPixels({ x: item.box.x, y: item.box.y });
  return <div style={{ position: 'absolute', left: px.x, top: px.y }}>📌</div>;
}
```

Going the other way (a pointer event → page space) is
`page.transform.fromPixels(px)`, and for raw client coordinates the page
context has `page.toContentPoint(clientX, clientY)`.

## Tools that use the PDF file's numbers

The PDF file stores positions in its own numbers, with y going up, and a page can sit anywhere in
them. You only meet those numbers beside a tool that reads them, such as iText, PDFBox or Acrobat
JavaScript. `page.pdfCropBox` says where the page sits in them, and `pdfRectOf()`, `pdfPointOf()`,
`pageBoxOf()` and `pagePointOf()` convert; see [Coordinates](/docs/engine/concepts/coordinates).

## Cheat sheet

| You're doing…                                      | Use              | Shape                                    |
| -------------------------------------------------- | ---------------- | ---------------------------------------- |
| Annotations, text, search, selection, `reveal`     | page space       | `{ x, y, width, height }` and `{ x, y }` |
| Drawing DOM/canvas right now                       | `page.transform` | pixels — convert, never store            |
| Talking to a tool that reads the PDF's own numbers | `pdfRectOf()`    | `{ left, bottom, right, top }`           |

**Bringing your own coordinate system?** Page space is a plain y-down frame in points — one
affine transform maps it into your world.
