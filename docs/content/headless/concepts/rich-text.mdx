# Rich text

A text box (a free text annotation) can mix styles: a bold word, a red sentence, a bigger heading.
Double-click the box below, select a word, and use the buttons, or press `Ctrl`/`Cmd` with `B`, `I`
or `U` while you type:

<Example name="annotation/rich-text" mode="open" />

## How it's stored

A text box has a **body style**, which is how its text looks by default, and **paragraphs** of
**runs**. A run is a piece of text with the styles it changes, and nothing else: a bold word in a
regular box is one run with `{ weight: 700 }`.

```ts
annotation.richText;
// {
//   body: { family: 'Helvetica', size: 12, color: '#000000' },
//   paragraphs: [{ runs: [{ text: 'Paid ' }, { text: 'in full', style: { weight: 700 } }] }],
// }
```

The engine writes it the way Acrobat does, so the formatting is the same there. The engine docs
have the full model: [Free text](/docs/engine/annotations/free-text#rich-text).

## Format from your toolbar

The same calls work while someone types in a box and when boxes are only selected:

```ts
const annotation = useAnnotation();

await annotation.selection.update({ bold: true });
await annotation.selection.update({ fontSize: 24, fontColor: '#c00000' });
await annotation.text.toggleFormat('italic'); // italic on, or off if it already is
```

Where a change lands depends on what's selected:

- **Words selected while typing**: the change styles those words.
- **Otherwise**: it styles the whole text of every selected box.

A property that isn't about text, such as opacity or the border, always applies to the whole box.

To show the state in your toolbar, [`useSelectionFields()`](../annotations/selecting#a-style-panel)
reports it the same way. With words selected, `values.bold` is true when every selected word is
bold, and `mixed` lists what the words disagree on. With a caret or a selected box, it reports the
box's own style. Text boxes also give you `textFormat` fields, so a style panel shows the bold,
italic and underline buttons without extra code.

<Callout type="info">
  A word with its own style keeps it when the box changes: turn the whole box red, and the one blue
  word stays blue. To make a word follow the box again, write the paragraphs without that style.
</Callout>

## When it's saved

Typing is written after a short pause, at every format change, and when editing ends, so the engine
never gets half a word. `documents.download()` waits for the last write, so the file you download has
everything the user typed.

## Show your own fonts

The engine puts a font into the PDF, but the browser draws the text while people type, so it needs
the same font. Register the font with the engine, and give the browser the same file under the same
key:

```ts
import { mountWebFont } from '@embedpdf/react/runtime';

await engine.fonts.register({ key: 'brand-sans', data });
const unmount = await mountWebFont('brand-sans', data);
```

The key is the font's name in both places: `fontFamily: 'brand-sans'` on a text box. The standard
PDF fonts need nothing: Helvetica shows as `Helvetica, Arial, sans-serif`, and so on. More in
[Fonts](/docs/engine/documents/fonts).

## Draw your own text box

The annotation layer's text box already edits rich text. If you [draw text boxes
yourself](../annotations/custom-rendering), `useRichTextEditor()` makes your element the editor:
it draws the runs, turns typing back into runs, keeps the caret when the style changes, and handles
pasting, input methods and the format shortcuts:

```tsx
import { useRichTextEditor, type AnnotationRendererProps } from '@embedpdf/react/annotation';

function BrandedTextBox({ annotation, box, page }: AnnotationRendererProps) {
  const editor = useRichTextEditor(annotation, page);
  const { x, y, width, height } = page.transform.pageToViewRect(box);

  return (
    <div
      ref={editor.ref}
      className={editor.editing ? 'text-box editing' : 'text-box'}
      style={{ position: 'absolute', left: x, top: y, width, height, ...editor.style }}
    />
  );
}
```

`editor.style` is the box's body style as CSS: font, size, color and alignment. The formatting
calls above work on your element as they do on the built-in one.
