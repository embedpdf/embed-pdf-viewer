# How it works

A headless viewer is a few parts that always work the same way. Learn them once here, and every
plugin page reads the same: the same four hooks, the same kinds of settings and events, the same
checks.

## The viewer and its documents

`<Viewer>` holds the engine, the plugins and the open documents. Everything inside it can use them:

```tsx
<Viewer engine={engine} plugins={plugins} initialDocuments={[{ source }]}>
  <Toolbar />
  <DocumentGate fallback={<p>Opening…</p>}>
    <Stage>{() => <RenderLayer />}</Stage>
  </DocumentGate>
</Viewer>
```

A viewer can have several documents open, like tabs, and one of them is active. A component talks
to the active document unless you put it inside a `<DocumentScope>`, which is how a tab strip or a
side-by-side view gives each part its own document:

```tsx
<DocumentScope id={documentId}>
  <Stage>{() => <RenderLayer />}</Stage>
</DocumentScope>
```

`<DocumentGate>` renders its children only once the document is open, so the components inside can
count on it. See [Opening documents](../documents/opening).

## Plugins

A plugin adds one feature. You register it when you create the viewer, with its settings:

```ts
const plugins = [stagePlugin({ layout: 'horizontal' }), renderPlugin(), searchPlugin()];
```

Most plugins keep their state per document: each open document has its own search, its own
selection, its own zoom. A few belong to the whole viewer, such as translations, commands and stamp
libraries.

## The four hooks

Every plugin gives your components four hooks, each with one job:

| Hook                     | Gives you                                     | Re-renders your component    |
| :----------------------- | :-------------------------------------------- | :--------------------------- |
| `useSearch()`            | the plugin's API: everything it can do        | never                        |
| `useSearchState()`       | the data to show, such as the number of hits  | when that data changes       |
| `useSearchEvent()`       | a call to your function when something happens | never                        |
| `useSearchSettings()`    | the plugin's current settings                 | when a setting changes       |

Search is the example; every plugin follows the pattern: `useStage()` and `useStageState()`,
`useAnnotation()` and `useAnnotationEvent()`, and so on. A plugin without settings has no settings
hook, and one without events has no event hook.

```tsx
function SearchBox() {
  const search = useSearch();
  const { hitCount, activeHitIndex } = useSearchState();

  return (
    <>
      <input onChange={(event) => search.search({ text: event.target.value })} />
      <span>
        {activeHitIndex + 1} of {hitCount}
      </span>
      <button onClick={() => search.nextHit()}>Next</button>
    </>
  );
}
```

- **Do things with the API hook.** Its object never changes, so it's safe in effects and callbacks.
- **Show things with the state hook.** To re-render only when one value changes, pass a function
  that picks it: `useSearchState((state) => state.hitCount)`.
- **React to things with the event hook.** It listens while the component is mounted:

  ```ts
  useSearchEvent(
    (search) => search.onCompleted,
    ({ hitCount }) => announce(`${hitCount} matches`),
  );
  ```

A few hooks read one specific thing and are named after it, such as `useAnnotationList(filter)`,
`usePageList()` or `useSurface(id)`.

## Layers and overlays

What you draw goes in one of two places.

**Layers** draw inside each page. The Stage calls its children once per visible page, and each layer
draws for that page. Later layers sit on top:

```tsx
<Stage>
  {() => (
    <>
      <RenderLayer annotations={false} />
      <SearchLayer />
      <SelectionLayer />
      <AnnotationLayer />
    </>
  )}
</Stage>
```

A layer zooms, scrolls and rotates with its page, and you never convert a position: everything a
plugin gives you is in page coordinates, and the layer places it.

**Overlays** float above the pages, attached to something on them: a menu next to the selected
text, a card next to an annotation. They go in the Stage's `overlay`, which keeps them attached
while the user scrolls and zooms. See [Menus over the page](../ui/anchored).

## Settings

A plugin's settings are the options you pass when you register it, and each plugin page lists them
under **Settings**. Some plugins let you change them while the app runs, for example when the user
picks another layout:

```ts
stage.updateSettings({ layout: 'grid' });
stage.resetSettings(); // back to what you registered
```

Every plugin with live settings has the same three calls, a `useStageSettings()`-style hook, and an
`onSettingsChanged` event.

## Checks before you act

Anything the user may not be allowed to do has a check with the same name:
`annotation.canCreate()`, `search.canSearch()`, `pageEdit.canEdit()`. Use them to hide or disable
buttons. The engine checks every call again, so they keep your UI honest; they're not the guard.
See [Permissions](permissions).

## Good to know

### Code outside components

`onReady` gives you the viewer once it has started, for code that isn't a component: a keyboard
handler, an analytics hook, a test.

```tsx
<Viewer
  engine={engine}
  plugins={plugins}
  onReady={(viewer) => {
    const search = viewer.capability(SearchToken);
  }}
/>
```

Each plugin exports its token (`SearchToken`, `StageToken`, …). A `ref` on `<Viewer>` gives you the
same object.

### Plugins don't touch the page

Plugins hold state and logic, never HTML. The framework packages draw. That's why every plugin
works the same in React, Vue, Svelte and Angular, and why you can use a plugin's API in a test
without a browser.

### Coordinates

Every position is in points from the top-left corner of the page, with y going down. Layers and
overlays convert to pixels for you. See [Coordinates](coordinates).
