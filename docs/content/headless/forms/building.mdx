# Building forms

The form plugin can also add fields to a PDF, and change or remove the ones it has, so people can turn
any document into a form. Switch to **design mode**, pick a field tool, and click or drag on the page:

```tsx
const FIELD_TOOLS = [
  ['form-text', 'Text'],
  ['form-checkbox', 'Checkbox'],
  ['form-radio', 'Radio button'],
  ['form-combobox', 'Dropdown'],
  ['form-listbox', 'List'],
  ['form-signature', 'Signature'],
] as const;

function FieldPalette() {
  const interaction = useInteraction();
  const { activeToolId } = useInteractionState();

  return FIELD_TOOLS.map(([id, label]) => (
    <button key={id} aria-pressed={activeToolId === id} onClick={() => interaction.activateTool(id)}>
      {label}
    </button>
  ));
}
```

Building needs the [annotation plugin](../annotations) next to the form plugin: in design mode, fields
are boxes you select, move, resize and style like any annotation.

| Tool             | Places                              | A click makes |
| :--------------- | :---------------------------------- | :------------ |
| `form-text`      | A text box                          | 160 × 24      |
| `form-checkbox`  | A checkbox                          | 18 × 18       |
| `form-radio`     | A radio button                      | 18 × 18       |
| `form-combobox`  | A dropdown                          | 140 × 24      |
| `form-listbox`   | A list                              | 140 × 72      |
| `form-signature` | A field someone signs later         | 160 × 48      |

A see-through preview of the field follows the pointer, so people see where it lands before they
click. Drag instead of clicking for another size. The tool stays active, so placing ten checkboxes is ten
clicks.

## Design mode

The `form-edit` tool is design mode: fields stop being fillable and become boxes you can select, move
and resize. The `pointer` tool makes them fillable again:

```ts
interaction.activateTool('form-edit'); // design the form
interaction.activateTool('pointer'); // fill it in
```

## Change a field's settings

`useFormState().selectedField` is the field of the selected box, for a settings panel:

```tsx
function FieldSettings() {
  const form = useForm();
  const { selectedField: field } = useFormState();
  if (!field) return null;

  return (
    <>
      <input defaultValue={field.name} onBlur={(e) => form.update(field.ref, { name: e.target.value })} />
      <label>
        <input
          type="checkbox"
          checked={field.required}
          onChange={(e) => form.update(field.ref, { required: e.target.checked })}
        />
        Required
      </label>
    </>
  );
}
```

`update()` takes only what you change, with the same settings a field reads:

| Setting         | What it is                                                         |
| :-------------- | :----------------------------------------------------------------- |
| `name`          | The full name. Dots make groups: `customer.email`                  |
| `required`      | PDF apps ask for a value before the form is submitted              |
| `readOnly`      | People can't change the value                                      |
| `alternateName` | The tooltip, also read by screen readers                           |
| `defaultValue`  | What a reset puts back                                             |
| `options`       | For a dropdown or list: `{ label, value }` pairs                   |
| `maxLength`, `multiline`, `password`, `comb` | For a text box                        |

A field's look, such as its border, background and font, belongs to its box: change it like any
annotation's, with the [style panel](../annotations/selecting#a-style-panel).

## Add fields from code

`create()` takes the same settings the engine takes, with the page and the box for each place the
field shows:

```ts
const { field } = await form.create({
  family: 'combobox',
  name: 'country',
  options: [
    { label: 'Netherlands', value: 'NL' },
    { label: 'Belgium', value: 'BE' },
  ],
  widgets: [{ page: page.ref, rect: { x: 72, y: 252, width: 148, height: 20 } }],
});
```

A radio group is one field with a box per button, each with the value it stands for:

```ts
await form.create({
  family: 'radio',
  name: 'plan',
  widgets: [
    { page: page.ref, rect: { x: 72, y: 136, width: 16, height: 16 }, exportValue: 'monthly' },
    { page: page.ref, rect: { x: 72, y: 166, width: 16, height: 16 }, exportValue: 'yearly' },
  ],
});
```

A field placed with a tool gets a name like `text_1`; rename it in your settings panel. Every
family's settings are on [Creating form fields](/docs/engine/forms/authoring).

## Remove a field

```ts
await form.delete(field.ref);
```

This removes the field and every box it has. To remove one box of a field that shows in several places,
such as a reference number on every page, use `form.removeWidget(field.ref, widget.ref)`.

## Events

```ts
useFormEvent(
  (form) => form.onFieldCreated,
  ({ field }) => selectField(field),
);
```

| Event            | Fires when                        | Carries            |
| :--------------- | :-------------------------------- | :----------------- |
| `onFieldCreated` | A field was added                 | `field`, `origin`  |
| `onFieldUpdated` | A field's settings changed        | `field`, `origin`  |
| `onFieldDeleted` | A field was removed               | `ref`, `origin`    |

## Permissions

| Permission         | What it allows                          | Check               |
| :----------------- | :-------------------------------------- | :------------------ |
| `doc.forms.modify` | Adding, changing and removing fields    | `form.canDesign()`  |

Hide the field tools when `canDesign()` is false.

## Good to know

### Fields and boxes

A field is the data: its name, its value, its settings. A **widget** is a box where the field shows on
a page. Most fields have one; a radio group has one per button, and a field can show on several pages,
all with the same value.

### Signature fields

A signature field is a place for someone to sign later. Signing it is on [Signatures](signatures).
