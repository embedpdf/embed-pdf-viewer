## Open a document later

`useDocuments()` opens documents while the app runs, for example one the user picked:

<Snippet name="documents/open-button" />

`open()` resolves with `{ document }` once it's open, and the new document becomes the active one.
Pass `{ activate: false }` to open it in the background.

<Fw only="angular">

When an input or a route parameter names the document, give it to the Stage instead:
`<epdf-stage [document]="source()">` opens the document, and when the signal changes, it opens the
new one and closes the old one.

<Engine local>

```ts
import { Component, computed, input } from '@angular/core';
import { EpdfRenderLayer } from '@embedpdf/angular/render';
import { EpdfPageTemplate, EpdfStage } from '@embedpdf/angular/stage';

@Component({
  selector: 'app-contract-page',
  imports: [EpdfStage, EpdfPageTemplate, EpdfRenderLayer],
  template: `
    <epdf-stage [document]="source()">
      <ng-template epdfPage>
        <epdf-render-layer />
      </ng-template>
    </epdf-stage>
  `,
})
export class ContractPage {
  /** `/contracts/:id`, bound with `withComponentInputBinding()` */
  readonly id = input.required<string>();
  protected readonly source = computed(() => ({ kind: 'url', url: `/files/${this.id()}.pdf` }) as const);
}
```

</Engine>

```ts
import { Component, computed, input } from '@angular/core';
```

## Where a document comes from

<Engine local>

| Source                              | What it is                                                        |
| :---------------------------------- | :---------------------------------------------------------------- |
| `{ kind: 'url', url }`              | A file the viewer fetches. The URL can be relative to your site.  |
| `{ kind: 'bytes', bytes }`          | A file you already have: an upload, a file picker, a download.    |
| `async (signal) => source`          | Anything else: a function that returns one of the above.          |

A function is how you add your own fetch, such as one with a login header. The viewer calls it
under the document's loading state, and `signal` cancels the download if the user closes the
document first:

```ts
const source = async (signal: AbortSignal) => {
  const response = await fetch(`/api/files/${id}`, { headers: { authorization }, signal });
  return { kind: 'bytes', bytes: await response.arrayBuffer() };
};
```

</Engine>

<Engine cloud>

| Source                                   | What it is                                                         |
| :--------------------------------------- | :----------------------------------------------------------------- |
| `{ kind: 'token', token }`               | A document your backend gave the user a token for.                 |
| `{ kind: 'share', shareToken }`          | A document opened with a public share link.                        |
| `{ kind: 'id', id }`                     | A document by its id, when the engine has a token for the user.    |

Pass `token` as a function, so a long session always has a fresh one. See
[Authentication](/docs/engine/authentication).

</Engine>

## Who the user is and what they may do

<Engine local>

Tell the viewer who the user is and what they may do, once. Every document it opens uses them:

<Snippet name="documents/identity-scope" />

- **`identity`** is who the user is. Their `displayName` becomes the author of the annotations they
  make.
- **`scope`** is what they may do, as a list of permissions. Leave it out and they may do
  everything; the engine reminds you once in the console.

A document can have its own, which replace the viewer's for that document:

```ts
const initialDocuments = [{ source, scope: ['doc.open', 'doc.render'] }]; // this one is read-only
await documents.open(source, { scope: ['doc.open', 'doc.render'] }); // and so is this one
```

[Permissions](../concepts/permissions) lists every permission.

</Engine>

<Engine cloud>

Who the user is and what they may do come from the document's token, so the server decides. See
[What a token carries](/docs/engine/authentication#what-a-token-carries).

</Engine>

## Close a document

```ts
await documents.close(document.id);
```

Closing frees the document's memory in the engine. The next document becomes the active one.

## Methods

What `useDocuments()` gives you for opening and closing documents and reading their pages. Tabs and
the active document are on [Several documents](tabs#methods), downloading and printing on
[Saving & downloading](saving#methods).

| Method                     | What it does                                                                                                                                                               |
| :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open(source, options?)`   | Opens a document and makes it the active one. Resolves `{ document }` once it's ready, or locked with a password; rejects when it can't be opened. [Open a document later](#open-a-document-later) |
| `openAll(documents)`       | Opens several documents, as `initialDocuments` does: every tab appears at once, in order, and the one marked `active` (or the first) becomes the active one. A failure shows in that document's `status` instead of throwing. |
| `unlock(id, { password })` | Unlocks a locked document. Rejects on a wrong password, and the document stays locked so you can ask again. [Loading, errors and passwords](#loading-errors-and-passwords) |
| `retry(id)`                | Tries a failed document again, with the same source and options. Resolves like `open()`.                                                                                     |
| `close(id)`, `closeAll()`  | Closes one document, or every document, and frees its memory. [Close a document](#close-a-document)                                                                        |
| `get(id)`                  | A document's fields, the ones [`useDocument()`](#state) gives you, or `null` when it isn't open                                                                             |
| `listPages(id?)`           | The document's pages, in order. In a component, use [`usePageList()`](../viewing/page-view#pick-the-page).                                                                  |
| `getPage(page, id?)`       | One page, by its `ref` or its index, or `null` when the document doesn't have it                                                                                           |
| `getPageIndex(ref, id?)`   | A page's position, from 0, or `-1` when the document doesn't have it                                                                                                       |
| `getRevision(id?)`         | A number that goes up each time pages are added, removed, moved or rotated; `-1` with no document                                                                          |

`options` for `open()` are `name` (what its tab shows), `activate: false` (open it in the
background), `password`, and, on the local engine, `scope` and `identity`. Without an `id`, the page
methods use the document in scope: the one a [`<DocumentScope>`](tabs#talk-to-a-specific-document)
around your component names, or else the active one. To stop an open that's still loading, close the
document: that cancels its download too.

## State

`useDocument()` gives you the document a component talks to: the active one, or the one its
`<DocumentScope>` names.<Fw only="react"> Your component re-renders when a value changes.</Fw><Fw only="vue"> Its fields are refs: your template updates when one changes.</Fw><Fw only="svelte"> It's one reactive object: read its fields, and your markup updates when they change.</Fw><Fw only="angular"> Each field is a signal: read it in a template or a `computed()`, and your view updates when it changes.</Fw> Outside a component,
`get(id)` gives the same fields.

| Field               | What it is                                                                                                   |
| :------------------ | :----------------------------------------------------------------------------------------------------------- |
| `id`                | The document's id, for `close(id)`, `unlock(id, …)` and `<DocumentScope>`                                    |
| `name`              | The name its tab shows, from `open()` or `rename()`                                                          |
| `status`            | `'loading'`, `'locked'`, `'ready'` or `'error'`                                                              |
| `pageCount`         | How many pages it has; `0` until it's ready                                                                  |
| `hasUnsavedChanges` | Whether it has changes that weren't downloaded yet. [Warn before changes are lost](saving#warn-before-changes-are-lost) |
| `passwordProvided`  | When it's locked: whether a password was tried and was wrong                                                 |
| `error`             | Why it couldn't be opened, when `status` is `'error'`: `{ code, message }`                                   |

Every open document, with the same fields, comes from [`useDocumentsState()`](tabs#state).

## Events

<Snippet name="documents/open-failed" />

| Event            | Fires when                                          | Carries                     |
| :--------------- | :-------------------------------------------------- | :-------------------------- |
| `onOpened`       | A document is open and ready                        | `documentId`, `info`        |
| `onOpenFailed`   | A document couldn't be opened                       | `documentId`, `error`       |
| `onLocked`       | A document needs a password                         | `documentId`, `passwordProvided` |
| `onClosed`       | A document was closed                               | `documentId`                |
| `onPagesChanged` | Pages were added, removed, moved or rotated         | `documentId`, `pages`, `revision` |

Switching the active document is on [Several documents](tabs#events).

## Good to know

### Opening large files

<Engine local>

The local engine needs the whole file before it can show the first page, so a large PDF on a slow
connection takes as long as its download.

<CloudPdfCallout
  title="Open a 500 MB PDF in a second"
  href="https://www.cloudpdf.com/docs/headless/documents/opening"
  cta="Open documents with CloudPDF"
>

With CloudPDF, the file stays on your server. The viewer asks only for the pages on screen, as
images, so the first page shows at once whatever the file's size, and a user who may not download
the file never receives it.

</CloudPdfCallout>

</Engine>

<Engine cloud>

The file stays on your server: the viewer asks only for the pages on screen, so the first page shows
at once whatever the file's size.

</Engine>

### `initialDocuments` is read once

<Fw only={['react', 'vue', 'svelte']}>

Like `engine` and `plugins`, the viewer reads `initialDocuments` when it mounts. To open another
document later, use `documents.open()`.

</Fw>

<Fw only="angular">

Like `engine`, `provideEmbedPdf()` reads `initialDocuments` once, when the viewer starts. To open
another document later, use `documents.open()`, or give the Stage a `[document]` that changes.

</Fw>

### Several documents

A viewer can hold several documents at once, like tabs. See [Several documents](tabs).
