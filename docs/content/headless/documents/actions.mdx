# Actions & scripts

A PDF can do things by itself: a button that resets a form, a field that adds up others, a link that
opens a website, a script that runs when the document opens. The actions plugin runs them, with
rules you choose. Register it, and install the browser's defaults for opening websites and printing
once, near the top of your viewer:

```tsx
import { actionsPlugin, useActionsUiAdapter } from '@embedpdf/react/actions';

const plugins = [/* … */ actionsPlugin()];

function ViewerShell() {
  useActionsUiAdapter();
  return (/* your viewer */);
}
```

Without it, the plugin still runs what stays inside the viewer, such as going to a page or resetting
a form, but it won't open a website or a print dialog.

## What runs

| Action                             | By default                                                        |
| :--------------------------------- | :---------------------------------------------------------------- |
| Go to a page or a destination      | Runs                                                              |
| A viewer action, such as next page | Runs                                                              |
| Show or hide a form field          | Runs                                                              |
| Reset a form                       | Runs                                                              |
| Open a website                     | Goes to your UI adapter when the user clicked; reported otherwise |
| Print                              | Goes to your UI adapter when the user clicked; never on its own   |
| Submit a form                      | Goes to your UI adapter when the user clicked; never on its own   |
| JavaScript                         | Off, until you turn it on                                         |

Actions that start a program, open another file on the user's computer, play media or import data
never run.

## Turn on JavaScript

Many forms calculate totals, check values and format dates with JavaScript. Turn it on:

```ts
actionsPlugin({ javascript: { enabled: true } });
```

Scripts run in a sealed sandbox: they can read and change the document's form fields and move
between pages, but they can't reach your app, the page's HTML or the network. Each script has a
time budget, so a script that loops forever is stopped instead of freezing the viewer.

A script can ask who the user is (`identity.name` in Acrobat's JavaScript). It gets the user the
document was opened for, and you can add the fields scripts often ask for:

```ts
actionsPlugin({
  javascript: { enabled: true, identity: { corporation: 'Acme', email: 'dana@acme.com' } },
});
```

## How websites open, printing and alerts

`useActionsUiAdapter()` installs the browser's defaults: a website opens in a new tab after a safety
check, printing opens the print dialog, and a script's alert shows the browser's alert. Replace any
of them with your own UI:

```tsx
useActionsUiAdapter({
  openUri: (uri) => {
    if (confirm(`Open ${uri}?`)) window.open(uri, '_blank', 'noopener');
  },
  alert: (message) => toast(message),
});
```

| Handler   | Called when                                               |
| :-------- | :-------------------------------------------------------- |
| `openUri` | An action opens a website or an email address             |
| `print`   | An action or a script asks to print                       |
| `alert`   | A script shows a message                                  |
| `gotoPage`| A script moves to a page                                  |

## Change the rules

Each kind of action has a rule for each way it can start: a click by the user (`user`), the pointer
moving over something (`hover`), or the document opening or closing (`lifecycle`):

```ts
actionsPlugin({
  policy: {
    uri: { user: 'adapter', hover: 'block', lifecycle: 'block' }, // websites only on click
    javascript: { lifecycle: 'block' }, // no scripts when the document opens
  },
});
```

| Rule        | Means                                                    |
| :---------- | :------------------------------------------------------- |
| `'allow'`   | Run it                                                   |
| `'adapter'` | Hand it to your UI adapter, which decides                |
| `'report'`  | Don't run it; report it in `onDiagnosticReported`        |
| `'block'`   | Don't run it                                             |

The rules can change while the app runs, for example when the user trusts a document:

```ts
actions.updateSettings({ policy: { javascript: { lifecycle: 'allow' } } });
```

## Run an action from code

```ts
const actions = useActions();

await actions.executeNamed('NextPage');
```

`executeNamed` runs a viewer action by its name: `'NextPage'`, `'PrevPage'`, `'FirstPage'`,
`'LastPage'` or `'Print'`. It follows the same rules as a click.

## Settings

Set them when you register the plugin. `policy` can also change while the app runs, with
`actions.updateSettings({ policy })`.

| Setting               | What it does                                                   | Default           |
| :-------------------- | :------------------------------------------------------------- | :---------------- |
| `javascript.enabled`  | Run the document's JavaScript                                  | `false`           |
| `javascript.identity` | Who scripts think the user is, on top of the document's user   | the document's user |
| `policy`              | The rules above, per kind of action and per origin             | as in the table   |
| `triggers`            | Run actions of the `document`, its `page`s, or `annotation`s   | all `true`        |
| `openSequence`        | When the document's opening actions run: `'auto'`, `'off'`     | `'auto'`          |

## Events

```ts
useActionsEvent(
  (actions) => actions.onDiagnosticReported,
  ({ code, action }) => console.warn(`Action ${action} was not run: ${code}`),
);
```

| Event                   | Fires when                                                   | Carries                     |
| :---------------------- | :----------------------------------------------------------- | :-------------------------- |
| `onExecuted`            | Actions ran                                                  | `result`, `source`          |
| `onDiagnosticReported`  | An action was blocked, reported or couldn't run              | `code`, `action`, `source`  |
| `onScriptFailed`        | A script threw an error                                      | `error`, `source`           |

## Permissions

Actions don't need a permission of their own, but some things they do do: printing needs
`doc.print`, and changing a form field needs `doc.forms.fill`. An action the user may not perform
is reported, never run.

## Good to know

### When opening actions run

With `openSequence: 'auto'`, the actions a document runs when it opens wait for the first sign of a
person: the UI adapter being installed, or a first click. So a document that plays a script on open
doesn't do it in a background tab nobody has looked at.

### Scripts and forms

Form calculations, validation and formatting are scripts too: with JavaScript on, the
[form plugin](../forms) runs them as people type. See [Filling forms](../forms).
