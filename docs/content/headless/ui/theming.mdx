# Colors & theming

Every color EmbedPDF draws on the screen, such as the text selection, search highlights and the
handles of a selected annotation, is a setting with a sensible default. Give the viewer your
accent, and every part follows it:

<Snippet name="ui/viewer-accent" />

Then fine-tune any part with its plugin's settings, such as the handles of an annotation:

```ts
annotationPlugin({
  chrome: {
    outline: { style: 'dashed' },
    handles: { shape: 'circle', fill: '#fce4ec' },
    rotationHandle: { stalk: false }, // no line between the box and the handle
  },
});
```

Every setting is typed, has its default, and is listed with its plugin under **Settings**. All of them
together are under [Every color](#every-color).

## Override from CSS

Every color setting can also come from a CSS variable, and a CSS variable always wins over a setting.
Use it for dark mode, for a different look per viewer, or to keep colors in your stylesheet:

```css
.pdf-viewer {
  --epdf-accent: #e91e63;
  --epdf-search-highlight: #7dd3fc;
}
```

Put the class on an element around your viewer; nothing needs importing. The rule is short: any CSS
variable wins over any setting. A part looks for its own variable, then its plugin's accent variable
(such as `--epdf-annotation-accent`), then `--epdf-accent`. Only when none is set does its setting
apply, then the setting it follows, then the built-in color.

Only paint comes from CSS: colors, line widths, dashes, shadows and opacity. How big a handle is,
where the rotation handle sits and how close snapping starts are settings only, because they decide
where a click lands.

## Dark mode

Set the variables inside a media query, or under a class your app already switches:

```css
@media (prefers-color-scheme: dark) {
  .pdf-viewer {
    --epdf-accent: #8ab4ff;
    --epdf-page-background: #2b2b2b;
    --epdf-readout-background: #f5f5f5;
    --epdf-readout-color: #111111;
  }
}

[data-theme='dark'] .pdf-viewer {
  --epdf-accent: #8ab4ff;
}
```

No code runs and nothing re-renders: the browser repaints.

## Change colors while the app runs

Every setting can change while the app runs. A plugin's settings change with `updateSettings()`:

```ts
annotation.updateSettings({ chrome: { accent: '#0f6e56' } });
```

<Fw only={['react', 'vue', 'svelte']}>

The viewer's `accent` and `page` follow the values you give it, like any other prop.

</Fw>

<Fw only="angular">

The viewer's `accent` and `page` change with `inject(EpdfViewer).updateSettings({ accent })`, since
the settings you give `provideEmbedPdf()` are read once.

</Fw>

For every part at once, such as an accent the user picks, set the variables on your wrapper.
`epdfTheme()` turns setting names into the variables, with autocomplete:

## Different looks for different viewers

Each viewer has its own settings. And a CSS variable applies to everything inside the element you set
it on, so two viewers on one page can each have their own colors from one stylesheet:

```css
.contract-viewer {
  --epdf-accent: #0f6e56;
}

.review-viewer {
  --epdf-accent: #993c1d;
}
```

## Every color

## What isn't here

**Colors saved in the PDF** belong to the document, not to your app, and look the same in every app
that opens the file:

- an annotation's color, set in each tool's defaults ([Tools & defaults](../annotations/tools));
- a redaction's fill and label ([Redaction](../annotations/redaction#settings));
- the look of a new form field ([Building forms](../forms/building));
- a stamp's colors ([Stamps](../annotations/stamps)).

## Good to know

### Tailwind

Set a variable with an arbitrary property on the wrapper, for example
`class="pdf-viewer [--epdf-accent:var(--color-pink-500)]"`.

<Fw only="angular">

### Inside your components

CSS variables pass through view encapsulation, so a variable set on a parent element reaches
EmbedPDF's elements inside your own components, whatever their `encapsulation`.

</Fw>

### Translucent defaults

Defaults such as "the accent at 35%" are mixed with `color-mix()`, which every current browser
supports, so they always match the color they follow.

### The ready-made Viewer

The [Viewer](/docs/viewer) builds its light and dark themes on the same variables, so a variable you
set works there too.
