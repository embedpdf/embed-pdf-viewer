# Toolbar

A viewer's toolbar has to fit a phone and a wide screen. `<Toolbar>` takes a list of what should be in
it, measures what fits, and makes room when it has to: labels become icons, a group folds into one
button, and what's left over goes into a "More" menu. You draw every button.

The items are [commands](commands), so each one already knows its label, icon, whether it's enabled,
and what it does. These are from the [standard commands](commands#the-standard-commands):

Resize the window, and the toolbar adjusts on its own. It measures real rendered widths, so a longer
translation or a bigger font just works.

## How it makes room

When the items don't fit, the toolbar takes these steps, in order, until they do:

1. **An item gets smaller**: from its first `variant` to the next, such as `'icon+label'` to `'icon'`.
2. **A group folds** into one button with a menu, when it has `collapse: 'menu'`, or into a dropdown
   with `collapse: 'select'`.
3. **An item moves into the "More" menu**, the least important first.

`importance` decides the order, from `1` (goes first) to `5` (never leaves the bar). An item without
one has its group's:

```ts
item('document:download', { importance: 5 }); // always visible
group('annotate', ['tool:note', 'tool:ink'], { importance: 2 }); // both go early
```

## Sections

`start`, `center` and `end` are the toolbar's left, middle and right. The center stays centered in the
space the other two leave. In a right-to-left language, `start` and `end` swap sides.

`orientation="vertical"` stands the toolbar on its side, for a rail beside the pages: `start`,
`center` and `end` become its top, middle and bottom, and it fits the height you give it, so give it
one. Every command draws at `'icon'`, so put its label in a tooltip. Groups fold and items move into
"More" the same way, and the default menus open beside it.

The second argument, `'page:go-to'` (a command of your own that opens a "Go to page" dialog), is what
the item becomes in the "More" menu when there's no room for it. `variants` lets it get smaller first, like a command's variants.

<Fw only="react">

`renderCustom` has one renderer per item name. A renderer that returns `undefined` draws the item's
command as a button instead. An item with no renderer is a native `<slot name>` element with that
button inside: in a web component, the host's children for that slot show there.

</Fw>

<Fw only="vue">

The `#custom` slot draws every custom item, by `name`. Where it draws nothing for one (a `v-if` that
doesn't match), the item's command shows as a button instead. Without the slot, each item is a native
`<slot name>` element with that button inside: in a web component, the host's children for that slot
show there.

</Fw>

<Fw only="svelte">

The `custom` snippet draws every custom item, by `name`, so draw something for each one: a snippet
can't fall back, and an item it skips shows nothing. Without the snippet, each item is a native
`<slot name>` element with the item's command as a button inside: in a web component, the host's
children for that slot show there.

</Fw>

<Fw only="angular">

Each `epdfToolbarCustom="name"` template draws the item of that name. An item with no template is a
native `<slot name>` element with its command as a button inside: in a web component, the host's
children for that slot show there.

</Fw>

The first element in your item that takes focus is where the toolbar's arrow keys stop. The rest of
its controls are your item's own, and a text field keeps Left and Right for its caret.

## Draw every part

| Prop                    | Draws                                                                  |
| :---------------------- | :--------------------------------------------------------------------- |
| `renderCommand`         | A button, for a command and its variant                                |
| `renderCustom`          | Your own items, by name                                                |
| `renderCollapsed`       | A folded group: its button and its menu                                |
| `renderSeparator`       | The line between groups                                                |
| `renderOverflowTrigger` | The "More" button                                                      |
| `renderOverflowMenu`    | The "More" menu, with its sections, items and the call to run each one |

<Fw only="react">

Every prop you leave out has a plain default, so you can start with `renderCommand` and add the rest as
you style them. `renderCollapsed` and `renderGroupTrigger` can return `undefined` for a group to leave
it to the default. `gap` and `separatorWidth` set the spacing, and `className` and `style` go on the
toolbar itself. `orientation` stands it on its side ([Sections](#sections)), and `aria-label` names
it for a screen reader when the page has more than one toolbar.

</Fw>

<Fw only="vue">

Every slot you leave out has a plain default, so you can start with `#command` and add the rest as
you style them. A slot that draws nothing for a part leaves that part to the default. `gap` and
`separator-width` set the spacing, and `class` and `style` go on the toolbar itself. `orientation`
stands it on its side ([Sections](#sections)), and `aria-label` names it for a screen reader when the
page has more than one toolbar.

</Fw>

<Fw only="svelte">

Every snippet you leave out has a plain default, so you can start with `command` and add the rest as
you style them. A snippet you pass draws every part of its kind. `gap` and `separatorWidth` set the
spacing, and `class` and `style` go on the toolbar itself. `orientation` stands it on its side
([Sections](#sections)), and `aria-label` names it for a screen reader when the page has more than
one toolbar.

</Fw>

<Fw only="angular">

Every template you leave out has a plain default, so you can start with `epdfToolbarCommand` and add
the rest as you style them. A template you give draws every part of its kind. `gap` and
`separatorWidth` set the spacing, and a `class` or `style` on `<epdf-toolbar>` styles the toolbar
itself. `orientation` stands it on its side ([Sections](#sections)). `<epdf-toolbar>` is the toolbar
to a screen reader, so an `aria-label` on it names it when the page has more than one toolbar.

</Fw>

Whatever you draw, the toolbar is one stop for the Tab key. The arrow keys along it move between its
items, past disabled ones, and Home and End go to its ends. The default menus open on their first
row: the arrow keys move, typing a letter jumps to the row that starts with it, Enter picks, and
Escape closes the menu and puts focus back on its button.

## Good to know

### Commands keep the buttons right

Because the items are commands, a button disables itself when its command can't run, shows as pressed
when it's active, and hides when the command isn't visible, with no code in the toolbar. Change a
permission or open a document, and the toolbar follows.

A group with `dependent: true`, like undo and redo, shows only while something in the bar that isn't
dependent shows: a bar left with only those draws nothing.

### Labels in the user's language

A command's label comes through [translations](translations), so the toolbar is in the user's language
and re-measures when it changes.

### The default look

When you don't draw a part yourself, the toolbar draws a plain one. Its colors come from CSS only,
because you're meant to replace them: `--epdf-toolbar-surface` (the "More" menu and folded groups,
`#ffffff`), `--epdf-toolbar-border` (`rgb(0 0 0 / 0.15)`) and `--epdf-toolbar-active` (a pressed or
open button, `rgb(0 0 0 / 0.12)`).
