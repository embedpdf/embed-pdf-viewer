## 3.0.0-next.15

### Minor Changes

- [#841](https://github.com/embedpdf/embed-pdf-viewer/pull/841) by [@bobsingor](https://github.com/bobsingor) – The page's layers say what they paint:
  - **`<RenderLayer>`** leaves out of the page picture what a layer on the page paints: the annotations while `<AnnotationLayer>` is there, the form fields while `<FormLayer>` is. Its `annotations` and `formFields` inputs decide for themselves when set; left out, a part no layer paints is drawn when the user may read it. Setting `annotations` to `false` next to an annotation layer is no longer needed.
  - **`<FormLayer>`** paints each field at rest as the engine draws it, in the state it shows, with the controls above while the tool fills forms. Hidden widgets get neither.
  - `canFill` and the signature checks take the field.

- [#841](https://github.com/embedpdf/embed-pdf-viewer/pull/841) by [@bobsingor](https://github.com/bobsingor) – `@embedpdf/svelte/history`: undo and redo (`useHistory`, `useHistoryState`, `useHistoryEvent`), with `historyPlugin` from `@embedpdf/plugin-history`.

  An annotation or a field that shows again before the page's next pictures arrive, such as one an undo brings back, shows its picture at once.

- [#869](https://github.com/embedpdf/embed-pdf-viewer/pull/869) by [@bobsingor](https://github.com/bobsingor) – `<SelectionClipboard target={() => area}>` copies only while focus is inside that element, for a page with more than one viewer, as `useCommandShortcuts({ target })` does for the other keys. Without `target` it copies anywhere on the page, as before.

- [#869](https://github.com/embedpdf/embed-pdf-viewer/pull/869) by [@bobsingor](https://github.com/bobsingor) – The `surfaceFocus(id, { select? })` attachment (`<input {@attach surfaceFocus('search')} />`) puts the cursor in its element when the surface `id` asks for it (`open(id, { focus: true })`, or a command whose `panel` says `focus`), also when the element mounts while the request is up; `select` selects an input's text, so typing replaces it.

- [#841](https://github.com/embedpdf/embed-pdf-viewer/pull/841) by [@bobsingor](https://github.com/bobsingor) – The form layer draws a widget with the painter (SVG text in the engine's own faces) while its look is pending or its picture is of an older version, and the engine's picture otherwise, taken from the form plugin: a typed value, a calculation or a restyle shows at once. The annotation layer applies the same rule, and takes its appearance scale from the render plugin: in design mode a form field being resized, or one restyled or newly placed, shows at once, drawn by the same painter. A scene's text is drawn in the faces its glyphs name, mounted while it shows. A text field's editor shows the text being typed where the engine will draw it, in the same face and size.

### Patch Changes

- [#841](https://github.com/embedpdf/embed-pdf-viewer/pull/841) by [@bobsingor](https://github.com/bobsingor) – The annotation, form, measurement and signature readers use the shared implementations in `@embedpdf/web` and the plugins; nothing they do changes. `SignerRow` is the signature plugin's own type now (the same fields, read-only).

- [#841](https://github.com/embedpdf/embed-pdf-viewer/pull/841) by [@bobsingor](https://github.com/bobsingor) – Without a document, a method that returns a promise (`form.setValue`, `redaction.markPage`) now returns a rejected promise with `not-ready`, so `.catch()` sees it; other methods still throw.

  The page context, the Stage's page layout and projector, the page view's transform, the page pointer listener, the scrollbar's geometry and presses, the tool cursors, anchored UI's measuring and the no-document stand-in now come from `@embedpdf/web` and `@embedpdf/core`, shared with every framework.

- [#841](https://github.com/embedpdf/embed-pdf-viewer/pull/841) by [@bobsingor](https://github.com/bobsingor) – The toolbar, commands, search, selection and link bindings use the shared implementations in `@embedpdf/core-ui`, `@embedpdf/web` and the plugins; nothing they do changes. `BoundCommand` comes from `@embedpdf/plugin-commands` (the same fields), and the toolbar's view types are aliases of core-ui's.

- [#869](https://github.com/embedpdf/embed-pdf-viewer/pull/869) by [@bobsingor](https://github.com/bobsingor) – The toolbar's default "More" menu no longer lays an invisible backdrop over the whole page: it closes on a press anywhere outside it and its button.

- [#841](https://github.com/embedpdf/embed-pdf-viewer/pull/841) by [@bobsingor](https://github.com/bobsingor) – Fix what `@embedpdf/svelte` gives an app that installs it from npm. Every relative import in the package names its file (`./search/readers.svelte.js`), so webpack, which doesn't guess extensions in an ES module package, and TypeScript's `node16` and `nodenext` resolution can follow them; before, only Vite-like bundlers could. The manifest no longer has a `svelte` field pointing at a source file that isn't published (the `svelte` export condition says it). `useRedactionState()` and `useSignatureState()` no longer name a package `@embedpdf/svelte` doesn't depend on in their types (the engine's), which a strict installer like pnpm doesn't link.

- [#841](https://github.com/embedpdf/embed-pdf-viewer/pull/841) by [@bobsingor](https://github.com/bobsingor) – `<RenderLayer>`'s tiles follow zooms and scrolls again:
  - The tile plane's effects read the page and the view through the whole page context, so every camera change released the page right after its new demand (and disposed and re-acquired the view's handle), and the tiles went. They now follow the page and the view only, and a `<PageView>` given another page still releases the old one.
  - A tile bound its picture again whenever a re-plan handed it a new `source` object, so every scroll step re-created its URL and hid it until it reloaded. It now binds again only for a new picture.
