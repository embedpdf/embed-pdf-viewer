# @embedpdf/plugin-fonts

## 3.0.0-next.20

### Major Changes

- [#941](https://github.com/embedpdf/embed-pdf-viewer/pull/941) by [@bobsingor](https://github.com/bobsingor) – Introduces the fonts plugin: a document's fonts, and how a browser draws text in them so typed text shows in the font program the engine writes with. `fontsPlugin()` is document-scoped. `getFontList()` mirrors `doc.fonts.list()`, read the first time something asks (`ensureLoaded()`, `fontsState`) and read again on `fonts.changed`. `resolve(request)` and `getProgram(displayHash)` wrap the engine's. `getFontCss(font)`, `getFaceCss(face)` and `getRunCss(run)` give a `FontCss`: a CSS `font-family` list naming the program, the fallbacks and the last resort, the weight and style, and the `programs` to mount where the text is drawn. The standard fonts and the last resort come from `@embedpdf/core-fonts` and need no list. `getFaceOfCssFamily(cssFamily)` reads a program's family back as its face. `onFontListChanged` fires when the list loads or changes. `getPaintFonts(font, text)` gives the fonts a box in `font` draws `text` with (`PaintFonts`, `@embedpdf/core-text`): the box's font, the fallbacks in the order the engine tries them for its style, and the last resort, with each program's coverage and metrics, measured by the kernel's `measurer`. It's `null` while they're found and the programs the text needs load, and `getPaintFontsEpoch()` moves when it may answer differently. Text a standard font draws whole needs neither; where the fonts can't be found or measured, the box's standard font with the last resort. A program the browser refuses (the measurer says so) is drawn as one it can't get: a face in its standard look-alike, in the CSS and the paint fonts alike, and a fallback passed over.

  The plugin lists, resolves and draws the fonts of a document on any engine, the cloud's included.

### Minor Changes

- [#941](https://github.com/embedpdf/embed-pdf-viewer/pull/941) by [@bobsingor](https://github.com/bobsingor) – Asking for the CSS of a font that isn't a standard one (`getFontCss`, `getFaceCss`) starts reading the document's fonts, after the asker's turn: an editor that draws in a document's font needs no `ensureLoaded()` of its own. A font's CSS names the fallbacks in the order the engine tries them for its style, so a bold font's Hebrew or Arabic draws in the bold fallback, as the engine writes it.

- [#941](https://github.com/embedpdf/embed-pdf-viewer/pull/941) by [@bobsingor](https://github.com/bobsingor) – A font's CSS names its programs once the browser has them all: until then the system's look-alikes draw the text, never the last resort's boxes. Asking for the CSS loads them, and `getPaintFontsEpoch()` moves when a CSS answer may change (the list changed, or a program arrived). A font the list doesn't name, or the list before it's read, draws in Helvetica, and the look-alikes after a document's or the engine's font are those of the standard font the engine falls back to for its face: no family is mounted by key any more. A read that asks for the document's fonts starts reading them after its turn, so asking from a render changes no state during it.
