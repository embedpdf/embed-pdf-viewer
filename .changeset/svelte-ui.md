'@embedpdf/svelte': minor

Add the Svelte bindings for your app's UI. `@embedpdf/svelte/commands` has `standardCommands`, `useCommands()`, `useCommandsSettings()`, `useCommandsEvent()`, `formatShortcut()`, `useCommand(id)` (a command with its label, state, `run` and formatted `shortcut`, as `{ current }`; pass the id as a function to follow a prop) and `useCommandShortcuts({ isMac?, target? })`, which turns every shortcut into a key while the component lives, only inside `target` (a function returning the element from `bind:this`) when given. `@embedpdf/svelte/toolbar` has `<Toolbar>`, which fits a bar into the width it has (labels become icons, groups fold, the rest goes into a "More" menu) and draws every part through a snippet with a plain default (`command`, `custom`, `collapsed`, `groupTrigger`, `separator`, `overflowTrigger`, `overflowMenu`), `useStripView()`, and the schema helpers (`group`, `item`, `custom`, …). `@embedpdf/svelte/shell` has `useShell()`, `useShellState()`, `useShellEvent()` and `useSurface(id)`, one panel's `isOpen` and `props` read live with `open`, `close` and `toggle` that work as plain handlers. `@embedpdf/svelte/i18n` has `useI18n()`, `useI18nState()`, `useI18nSettings()`, `useI18nEvent()` and `useT()`, a translate function that reads the current language each time it's called, so a template that calls it follows a language switch. Each entry re-exports its plugin, so registration travels with the UI.
