`documents.import` gains the provider-neutral `connection` source kind: requests name an operator-registered connection plus a key (and an opaque, provider-interpreted `revision`), so provider details never enter the public wire contract. Connections are configured via the `CLOUDPDF_IMPORT_CONNECTIONS` env registry across all four storage families — S3 and S3-compatibles (revision = VersionId), GCS (revision = generation, with stat-generation read pinning), Azure Blob (revision = version id, keyless DefaultAzureCredential), and filesystem roots (api-token only structurally, realpath symlink-escape containment, no revisions — pin with expected.sha256). Authorization is boot-validated and fail-closed: per-connection credential classes (default: api-token only), tenant allowlists, and a scope union — whole-bucket (api-token only, structurally), shared prefixes, or a `tenants/{tenantId}/` template that binds the authenticated tenant to its own slice at any tenant count. Self-imports are refused via canonical per-family backend fingerprints (AWS namespace vs custom endpoints; GCS bucket; Azure account+container; fs path containment in either direction). Every import upserts a structured provenance row in the new `document_imports` table (migration 026): source identity, requested/resolved revision, credential class, actor, attempts, and sanitized outcome — the same table phase 3b's async worker will drive. A shared import-source conformance suite pins the URL, S3, GCS, Azure, and fs adapters to identical open() semantics.
