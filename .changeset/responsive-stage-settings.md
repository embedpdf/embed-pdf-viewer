Responsive settings — container queries for the settings bag. The stage's settings gain `@container`-style conditional blocks: `stagePlugin({ responsive: [{ name: 'compact', when: { maxWidth: 600 }, settings: { padding: 8, spread: 'none' } }, …] })` declares ordered rules whose `when` queries THE BOX the stage was told about (`minWidth`/`maxWidth`/`minHeight`/`maxHeight`/`orientation`, all inclusive, AND-ed — or a `(box) => boolean` predicate for anything else the box can answer). All matching rules apply in source order, later winning per key; effective settings = base ⊕ matching patches. The query vocabulary is deliberately just the box: a headless, DOM-free stage knows exactly one environmental fact — its viewport — so rules are space-aware, not device-aware (an embedded 500px pane on a desktop is compact too, and each stage instance — each `view-manager` pane — resolves against its own box; no user-agent sniffing, no global mobile flag; pointer modality stays per-event on `PointerSample`). Semantics, stated plainly: runtime setters and `update()` write the BASE, and a matching rule wins until its rule stops matching; rules assert at TRANSITIONS (box/base/rules changes), not continuously — between crossings interaction owns the state, so a pinch-zoomed level survives a resize unless a rule actually flips, while a rule containing `zoom` re-fits at the crossing (the rotate-an-iPad behavior) and then leaves the pinch alone. Crossings ride the existing settings engine: each rule patch lands through the same effect registry (`reflow`/`scene`/`refit`/`reclamp`) with the same invariants, so a breakpoint that flips `spread` relayouts with the reading anchor held, exactly like a hand-written `update()`. A rule with a `name` is a queryable, reactive fact — `stage.matches('compact')`, `stage.activeRules()` — and a named rule with no settings is a pure shared breakpoint the app chrome can key its own presentation off (one definition serving layout math and UI). `setResponsive(rules)` swaps the rule list at runtime; `applyViewState` restores snapshots as base, so a view saved on a desktop restores compactly on a phone. Ships with one default rule — `{ name: 'compact', when: { maxWidth: 600 }, settings: { padding: 8 } }` — giving every embedder the thin phone gutter with zero configuration (pass `responsive: []` to opt out; note this changes default compact-container padding from 24 to 8). Pure resolver (`resolveResponsive`, `matchesQuery`, `boxOf`) exported and property-tested in a `responsive.ts` sibling module.
