Phase 2 — trigger sources. The trigger vocabulary widens to annotation `/AA` events (cursorEnter/Exit, mouseDown/Up, focus/blur), page lifecycle (open/close/visible/invisible with central ISO-ordered fan-out: `/O` before the `/PO` set, the `/PC` set before `/C`), and the document-open sequence (§3.9: `openDestination` as a synthesized lifecycle goto, then `openAction`, latched on adapter install / first user dispatch / headless config). `dispatch()` now submits synchronously and resolves everything inside the serial queue — submission order IS execution order, and it never rejects (`refused` + `trigger-failed` instead). It returns an `ActionTriggerResult` with per-step truth (`onAction` still fires once per tree with its real paths); origin derives centrally from the trigger and cannot be claimed by callers. A lifecycle coordinator buffers stage's new `reportPageState` reports behind the open barrier (no phantom opens on restored views) and caps consecutive programmatic rounds (`cascade-budget`) so `/O`→GoTo loops terminate. `/A` shadows `/AA U` per ISO Table 197. Adds the shared `createHoverPump` (Exit→Enter as one ordered pair, intermediates skipped) and config gates `triggers`/`openSequence`. Removes the unused `registerTriggerSource` stub (pre-release surface trim).
