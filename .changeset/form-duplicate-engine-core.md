New change op `forms.copy`, and `doc.forms.copy(fields, { page?, offset?, values?, widgets?, objectNumbers? })` for it: a new field from each field named, made as one change that one undo takes away. A copy has its source's settings, scripts and default value, and each widget's place, look, flags and actions, moved by `offset` or put on `page`. It is named after its source with the next free number (`email` becomes `email_2`, `billing.name` becomes `billing.name_2`), and it has its source's value unless `values` is `false`; a signature never comes along. `widgets` names the widgets to copy when it isn't all of them. The result holds the new fields, their widgets, `refMap` and `dropped`, with the reasons a form import uses, and its events are one `forms.created` per field. `planFormCopies` is the rule itself, without zod, for a viewer that shows the copies before the engine answers; `copyNameOf` and `fieldNameTaken` name a copy. The op arrived in 3.2 (`CHANGE_KIND_SINCE`), so an older server is never sent it and an older client reads everything again. `runFormCopyConformance` checks an engine against it. A form import and a copy now also carry a widget's check style and its dash pattern.
