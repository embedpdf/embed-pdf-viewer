The documents capability prints. `print(id?, { pages, includeAnnotations, onProgress })` makes the pages as they print (layers, annotations and form fields by their print settings) and hands them to the host's print dialog. `preparePrint(id?, options)` does that ahead and resolves `{ quality, pageCount, needsTap, print(), dispose() }`, so a dialog prepares when the user presses Print and then prints; its `print()` prepares again when the document changed since. `needsTap` is the printer's: `true` where printing works only from a tap (Safari), so a dialog asks for another tap once the print is ready. `getPrintQuality(id?)` says how it prints: `{ kind: 'pdf' }` — a copy of the pages as they print (`pages.extract` with `flatten: { usage: 'print' }`), sharp text and lines — with `doc.print.high`, a right to keep the copy (`doc.download` or `doc.download.flattened`) and a printer that prints PDFs; else pictures, `{ kind: 'images', dpi: 300 }` with `doc.print.high` or 150 DPI with `doc.print` only; `null` when it can't. When the printer turns the PDF down, preparing or printing, the same pages print as 300 DPI pictures. Form fields print whenever the user may read the form, with or without the annotations. Printing waits for changes still on their way, as a download does. The host hands the kernel its printer, `createKernel({ printer })` (`HostPrinter`, with `stagePdf` when it prints PDFs and `needsTap` when it prints only from a tap), and `canPrint()` is `doc.print` and a printer. A plugin runs the document's own around the print dialog with `ctx.aroundPrint(wrap)`; the test context's `print(run)` runs those wraps.
