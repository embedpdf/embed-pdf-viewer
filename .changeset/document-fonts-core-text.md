'@embedpdf/core-text': minor

Add `@embedpdf/core-text`: text laid out as the engine lays it out, so a viewer can draw what the engine will write before it has. `layoutField(text, fonts, options)` gives a form field's lines as runs, each in one font and one direction, at the x and baseline the engine writes them: the font each character is drawn in (the field's font, then the first fallback that has it, then the last-resort font), the Unicode bidirectional order of each line, line breaks, fitted sizes, alignment, combs, password and length limits. Fonts are `TextFont`s: `standardTextFont(name)` for the 14 standard fonts, or any font program with its coverage, line metrics and a measurer; `TextFonts<F>` carries the caller's own font type through to the runs, and a run says whether it is `plain`, drawn with kerning and ligatures off. A browser draws with `PaintFont`s, each with its CSS family, weight, style and program (`PaintFonts` for a box): `standardPaintFont(name)`, `lastResortPaintFont()`, `programPaintFont(info, program, measure)` for a program the engine reads (`doc.fonts.getProgram`) measured by the browser, and `defaultPaintFonts(fontFamily)`, a box's standard font with the last resort behind it. Also `matchGrapheme`, `paragraphLevels`, `lineLevels`, `visualOrder`, `firstStrongIsRtl` and `graphemesOf`.

A `FieldText` says the direction its lines read in (`rtl`): right to left when the field's first strong character is, as the engine draws it.

A comb draws a cursive script's letters in the forms the whole text gives them, as the engine does: a comb's `FieldRun` says whether its letter joins the cell before it and the one after it, in typing order (`joinsPrevious`, `joinsNext`), and is as wide as that joined form. Unicode's joining types come with it: `joiningTypeOf(codePoint)`, `graphemeJoiningType(grapheme)`, `joinsOf(graphemes, together)` (where each grapheme joins its neighbours, shaped together) and `joinedText(grapheme, joins)` (the grapheme with a joiner, U+200D, on each side it joins).
