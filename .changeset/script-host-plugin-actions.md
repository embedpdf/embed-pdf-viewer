THE JavaScript switch lives here now: `actionsPlugin({ javascript })` owns the per-document ScriptHost realm, registers the real `javascript` executor (page-scoped world prefetch → boot → run → owner-sink commits → surface, ALL inside the host transaction — the commit-inside-the-boundary law), and exposes the transaction port + `surfaceScriptResult` on `contract/host`. Owner commit sinks replace direct engine writes (`registerFormCommitSink` / `registerAnnotCommitSink` — each plugin commits AND reconciles its own model, so the PDF and the pixels can never diverge). Trigger provenance reaches executors (`ActionContext.event` + `eventOf`), and — full ISO — the Hide action routes by OWNING plane: field names and widget object numbers become form `setDisplay` effects, plain annotations become document flag patches; the session-visibility sink (`SessionEffectSink`/`registerSessionSink`) is REMOVED. `ActionUiAdapter` gains `alert`/`gotoPage` (+ print context) as the ONE UI port for every script effect, with the `doc.print` authority gate upstream and `onScriptDiagnostic`/`onScriptError` hooks. A deterministic per-dispatch JS node cap (`maxScriptNodesPerDispatch`) bounds `/Next` chains.

Scripting configuration is ONE environment that mints any number of realms. `createScriptRealmFactory` (internal) carries the session half of the switch — sandbox factory, identity (resolved from the OWNING document's claims plus embedder decoration), clock, seed, budget — and builds this document's own host plus DETACHED realms on demand. The host lens exposes `scriptRealm` (the transaction port + the budget consumers apply as their transaction aggregate; replaces `scriptTransaction`) and `createDetachedScriptRealm(target)` (a fresh, isolated realm for a document that is not displayed — stamp's asset documents; the caller owns its lifetime). Every `ScriptSurfaceResult` now names its `realm`: a detached realm has no document surface, so only alerts reach the adapter and print/goto/submit requests are suppressed with a `ui-effect-suppressed` diagnostic instead of acting on the viewer document. `surfaceScriptCommit` is the one place a K/V/C/F commit splits into its boot- and user-phase surfaces.
