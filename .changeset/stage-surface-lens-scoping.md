Shared Stage surface binding + lens-scoped interaction (structure review follow-up). React now keys page surfaces by `pon` — the durable page identity — instead of the mutable display index, so move/delete operations (page-edit) can no longer strand component state (bitmap refs, open editors) on the wrong PDF page; this matches the Angular adapter's `track p.pon`. The whole browser binding — ResizeObserver → `setViewport`, dppx-chain → `setDevicePixelRatio`, pointer-sample normalization, and the gesture controller — moved into ONE shared `createStageSurface(el, stage, { hub, source, zoomGestures })` in `@embedpdf/web` (structural interfaces, no plugin imports), so React and Angular can never drift; the framework components keep only their reactive glue. Interaction ownership is now ONE knob at the sample source — and that knob DEFAULTS ON: `<Stage>` / `<epdf-stage>` both forward the lens's pointer samples AND register its tool-gated pan-scroll handler whenever the interaction hub is present, so registering `interactionPlugin()` is the single opt-in and tools just work with zero component props (without the hub the routing is inert and the stage falls back to built-in drag-to-pan). Set `interaction={false}` on SECONDARY lenses (thumbnail rails) that should stay click-to-navigate. `stagePlugin({ interaction, panFallback })` is REMOVED (a handler can no longer exist without its input stream, and two flags can no longer disagree); `panFallback` moved to the Stage component. Samples carry the lens identity: `PointerSample.source` (stamped by the binding from the new `stage.lensId()`), and `registerHandler(handler, { source })` scopes a handler to one lens — with several stages on one document, a drag on one lens can never be captured by another lens's scroll handler (unstamped samples still route everywhere, so custom dispatchers keep working). `wheelZoomFactor` moved from `@embedpdf/plugin-stage` to `@embedpdf/web` (its domain is browser wheel classification, beside the controller that consumes it) and the gesture controller now defaults to it — callers can stop passing it; the plugin-stage export is REMOVED. Page drop-shadows are themeable via `--epdf-page-shadow` (CSS variable with the previous value as fallback) in both adapters. Doc honesty fixes: the capability's scheduler seam now states its host-frame-clock default plainly, and core-stage's header no longer claims `Scene` itself is serializable (its DATA is; the query methods are derived).
