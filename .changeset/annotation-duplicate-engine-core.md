New change op `annotations.copy`, and `doc.annotations.copy(refs, { page?, offset?, objectNumbers? })` for it: copies of annotations inside one document, made as one change that one undo takes away. A copy carries every field of its kind, `locked` included, and a stamp's drawing or an attachment's file, so `doc.download` isn't needed. It gets its own ref and a fresh `nm`, and the session is its author. Links between copies stay: a reply to an annotation that is copied too replies to that one's copy, so a copied group is a group of its own. The result holds the copies, `refMap` and `dropped`, with the reasons an import uses. `planAnnotationCopies(sources, placement)` is the rule itself, without zod, for a viewer that shows the copies before the engine answers. The op arrived in 3.2 (`CHANGE_KIND_SINCE`), so an older server is never sent it and an older client reads everything again. `runAnnotationCopyConformance` checks an engine against it. A copy stays within the bundle limits (`items`, `resources`, `resourceBytes` and `bundleBytes`); past one it is refused with `PayloadTooLarge`, and `details.limit` names the limit.
