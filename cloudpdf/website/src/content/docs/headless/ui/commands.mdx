# Commands & shortcuts

A **command** is one action of your viewer, like "zoom in" or "download", defined once: its label, its
icon, when it's enabled or active, what it does, and its keyboard shortcut. Toolbars, menus, a command
palette and the keyboard all run the same command, so they always agree. Register the plugin with the
commands you need:

`shortcut` is formatted for the user's platform: `⌘K` on a Mac, `Ctrl+K` elsewhere. The
[toolbar](toolbar) draws commands the same way.

There's always a command, so a button never checks for a missing one: an id no plugin registered
comes back labelled with its id, neither visible nor enabled, the way a turned-off command does,
and in development it warns once, with the closest id there is. Checking `visible` covers a
command that's turned off, not allowed or missing. `resolveCommand(id)` is the lookup for code,
and says `null` for an id it doesn't have.

## The standard commands

`standardCommands` covers what every viewer has, with labels in [every language you load](translations):

| Command                                              | Does                                         | Shortcut         |
| :--------------------------------------------------- | :------------------------------------------- | :--------------- |
| `zoom:in`, `zoom:out`                                | Zoom in or out                               | `Mod+=`, `Mod+-` |
| `zoom:fit-width`, `zoom:fit-page`                    | Fit the page's width, or the whole page      |                  |
| `page:next`, `page:previous`, `page:first`, `page:last` | Move through pages                        | `→`, `←`, `Home`, `End` |
| `view:rotate-clockwise`, `view:rotate-counterclockwise` | Turn the view                             |                  |
| `tool:pointer`, `tool:pan`                           | Switch tools                                 | `V`, `H`         |
| `tool:<id>`                                          | Any registered tool, such as `tool:highlight` |                 |
| `selection:copy`                                     | Copy the selected text                       | `Mod+C`          |
| `annotation:delete`                                  | Delete the selected annotations              | `Delete`         |
| `document:download`, `document:print`                | Download or print the document               | `Mod+S`, `Mod+P` |

Each one is enabled only when it can run: `selection:copy` needs a selection and permission to copy,
`annotation:delete` a selection the user may delete.

## Run a command from code

```ts
await commands.execute('zoom:in');
await commands.execute('review:approve', { args: { note: 'Looks good' } });
```

`execute()` resolves with `{ status: 'executed' }`, or `{ status: 'rejected', reason }` when the command
is disabled, hidden or unknown.

## A command palette

`searchCommands()` finds commands by their label, for a palette like the one in code editors:

```ts
const results = commands.searchCommands(query); // visible commands whose label or id matches
```

A disabled command is still in the results, so show it greyed out.

## Define a command

| Field         | What it is                                                                       |
| :------------ | :------------------------------------------------------------------------------- |
| `id`          | A unique name, by convention `area:action`                                       |
| `label`       | What the user sees, or `labelKey` for a [translated](translations) label         |
| `icon`        | Your icon's name; your buttons turn it into an icon                              |
| `shortcut`    | A key such as `'Mod+K'`, or a list of them                                       |
| `enabled`     | When it can run, as a function of the viewer's state                             |
| `active`      | When it shows as pressed, such as the current tool                               |
| `visible`     | When it shows at all                                                             |
| `run`         | What it does                                                                     |
| `requires`    | The [permissions](../concepts/permissions) it needs, such as `'doc.annotate.modify'`. Without them, it's hidden. |
| `categories`  | The features it belongs to, so you can [turn them off](#turn-features-off) together, such as `['annotations.highlight']` |
| `panel`, `menu`, `modal` | A command that opens a [panel, menu or dialog](panels) needs no `run`  |

`enabled`, `active` and `visible` get the viewer's state through `get(Token)`, and are asked again
whenever anything changes, so a button is always right without events or effects of your own.

## Turn features off

Put commands in categories, and turn a whole category off: its commands are hidden and refused,
wherever they appear. A category turns off every category under it, on whole dotted parts:
`annotations` also turns off `annotations.highlight`. The `disabledCategories` [setting](#settings)
turns categories off from the start, and while the app runs:

```ts
commands.disableCategory('annotations');
commands.enableCategory('annotations');
```

Turn off one command the same way, with `disableCommand(id)` and the `disabledCommands` setting. A
command that's turned off is refused by `execute()` too, and its shortcut does nothing.

## Methods

Everything `useCommands()` gives you.

| Method                                                                   | What it does                                                                                                                                         |
| :----------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- |
| `execute(id, { args?, documentId? })`                                    | Runs a command. Resolves `{ status, reason? }`: `'executed'`, or `'rejected'` with why. A `run` that throws rejects. [Run a command from code](#run-a-command-from-code) |
| `canExecute(id, documentId?)`                                            | Whether a command can run now: it's registered, enabled and visible                                                                                 |
| `resolveCommand(id, documentId?)`                                        | A command as a button shows it: label, icon, shortcuts, and whether it's enabled, active and visible. `null` for an unknown id. <Fw only={['react', 'vue', 'svelte']}>In a component, use `useCommand(id)`.</Fw><Fw only="angular">In a template, use the `epdfCommand` directive.</Fw> [Show a command](#show-a-command) |
| `getRefusal(id, documentId?)`                                           | Why a command won't run whatever the moment, as `{ reason, message }`: `'turned-off'` or `'not-allowed'`, with a sentence for the user. `null` when it may run, or can't only right now, and for an unknown id |
| `listCommands(documentId?)`                                              | Every command, resolved the same way, in the order they were added                                                                                  |
| `searchCommands(query, documentId?)`                                     | The visible commands whose label or id contains the query. [A command palette](#a-command-palette)                                                  |
| `listShortcuts()`                                                        | Every shortcut with its command, as `{ commandId, shortcut }`, for a keyboard help sheet. [Keyboard shortcuts](#keyboard-shortcuts)                 |
| `registerCommand(command, { replace? })`, `registerCommands(commands, { replace? })` | Adds one command, or several, while the app runs, and returns a function that removes them. An id that's taken is refused unless you pass `replace: true`. [Define a command](#define-a-command) |
| `getCommand(id)`, `hasCommand(id)`                                       | A command as you defined it, or `null`; whether it's registered                                                                                      |
| `listCommandIds()`                                                       | Every command's id, in the order they were added                                                                                                     |
| `disableCategory(category)`, `enableCategory(category)`                  | Turns a category off, with every category under it, or on again. [Turn features off](#turn-features-off)                                            |
| `setDisabledCategories(categories)`                                      | Replaces the list of categories that are off                                                                                                         |
| `getDisabledCategories()`, `isCategoryDisabled(category)`                | The categories that are off; whether one is, itself or through a category it's under                                                                |
| `disableCommand(id)`, `enableCommand(id)`                                | Turns one command off, or on again. [Turn features off](#turn-features-off)                                                                         |
| `setDisabledCommands(ids)`                                               | Replaces the list of commands that are off one by one                                                                                                |
| `getDisabledCommands()`, `isCommandDisabled(id)`                         | The commands that are off one by one; whether a command is off, by its id or through one of its categories                                          |
| `getSettings()`, `updateSettings(changes)`, `resetSettings()` | Reads the settings, changes them while the app runs, or goes back to what you registered. In a component, use `useCommandsSettings()`. [Settings](#settings) |

Leave out `documentId`, and a command runs and resolves for the document in scope: the one a
[`<DocumentScope>`](../documents/tabs#talk-to-a-specific-document) around your component names, or
else the active one. Every method that returns a promise also takes a `signal` in its options, to
cancel it.

## Settings

Set them when you register the plugin, and change them while the app runs with
`commands.updateSettings({ … })`; `commands.resetSettings()` goes back to what you registered, and
`useCommandsSettings()` gives you the current settings.

| Setting              | What it does                                          | Default |
| :------------------- | :---------------------------------------------------- | :------ |
| `commands`           | The commands your viewer has                          | none    |
| `disabledCategories` | Categories that start turned off, with every category under them | none    |
| `disabledCommands`   | Commands that start turned off, by id                 | none    |
| `notAllowed`         | What a command the scope doesn't allow does: `'hide'` leaves it out, `'disable'` shows it disabled with `disabledReason` | `'hide'` |

## Good to know

### Commands and permissions

A command that needs a permission says so with `requires: ['doc.annotate.modify']`. When the user
doesn't have it, the command isn't visible, so its buttons and menu rows are gone, and its shortcut
does nothing. With the `notAllowed: 'disable'` setting it shows disabled instead, and the resolved
command's `disabledReason` says why, for its tooltip: the i18n string for
`commands.notAllowed.<permission>` (dots and colons as dashes, such as
`commands.notAllowed.doc-print`), else `commands.notAllowed.default`. Keep `enabled` for what can't
run right now, such as **Copy** with nothing selected. The standard commands already say what they
need.
