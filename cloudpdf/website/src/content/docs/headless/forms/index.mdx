# Filling forms

Many PDFs are forms: text boxes, checkboxes, dropdowns, signature fields. Register `formPlugin()` and
put `<FormLayer>` in each page, and people can fill them in:

<Snippet name="forms/form-layer" />

<Example name="form/basic" />

Each field becomes a real HTML control, placed and styled like the field in the PDF: people type in text
boxes, tick checkboxes, pick from lists, and move between fields with Tab. A value is saved into the
document as it's entered, so it's there when the PDF is downloaded, and every PDF app shows it.

Each field has its full `name` (such as `billing.name`), its `family` (`'text'`, `'checkbox'`,
`'radio'`, `'combobox'`, `'listbox'`, `'pushbutton'` or `'signature'`), its value, and a `ref`: its

## Fill in a field

`setValue()` takes the same values a field reads:

```ts
await form.setValue(name.ref, { value: 'Ada Lovelace' }); // text
await form.setValue(agree.ref, { checked: true }); // checkbox
await form.setValue(plan.ref, { value: 'yearly' }); // radio group: the button's export value
await form.setValue(country.ref, { value: 'NL' }); // dropdown: an option's value
await form.setValue(toppings.ref, { selectedValues: ['cheese', 'olives'] }); // list
```

It runs the same checks and scripts as typing does, and resolves with `{ field, status }`: `status`
is `'applied'`, `'unchanged'`, or `'rejected'` when the form's own validation refused the value.

<Fw only="angular">

Your own inputs can fill in fields too. `form.controlOf(ref)` gives you a field as an Angular
`FormControl`: it holds the field's value, and fills in the field when the control changes, with
the same checks and scripts:

<Snippet name="forms/form-control" />

</Fw>

To fill many fields at once, such as from your backend, pass them by name:

```ts
await form.importValues({ 'billing.name': 'Ada Lovelace', 'billing.country': 'NL', agree: true });
```

## Check required fields

A form marks some fields as required. Check them before you submit or download:

```ts
const { valid, missing } = form.validate();

const widget = !valid && form.getWidget(missing[0].widgets[0]);
if (widget) stage.reveal(widget.page, { rect: widget.rect });
```

`missing` lists the required fields that are empty, in page order, so you can take the user to the
first one.

## Reset the form

```ts
await form.reset(); // every field, back to its default
await form.reset([name.ref, email.ref]); // some fields
```

## Move form data in and out

FDF and XFDF are the formats every PDF tool uses for form data: the values without the PDF.

```ts
const { bytes } = await form.export(); // XFDF; form.export('fdf') for FDF
await otherForm.import(bytes);
```

For your own backend, plain values are simpler:

```ts
const values = form.exportValues(); // { 'billing.name': 'Ada Lovelace', agree: true, … }
await form.importValues(values);
```

Fields are matched by their full name. A field the form doesn't have, or a value it can't take, is
skipped; the rest still land.

## Methods

What `useForm()` gives you for reading and filling. The verbs that change the form itself are
on [Building forms](forms/building#methods).

| Method                     | What it does                                                                                                                                   |
| :------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------- |
| `get(ref)`                 | One field, with its value, or `null` when the form has no such field. [Read the form](#read-the-form)                                           |
| `getValue(ref)`            | One field's value, in the shape `setValue()` takes, or `null`. In a component, use `useFormValue(ref)`.                                        |
| `getFieldForWidget(widget)` | The field a box belongs to, from the box's ref                                                                                                |
| `getWidget(widget)`        | A box's row: its page, its place (`rect`), its look and its state, or `null` when no page shows it                                             |
| `getWidgets(ref)`          | Every box a field shows in, as rows in the field's order: a radio group's buttons, or a field repeated on several pages                       |
| `listWidgets(page)`        | Each field box on a page, with its place, its control, its value and whether it can be filled. For drawing the fields yourself.                |
| `getWidgetAt(page, point)` | The field box under a point on a page, with its field, or `null`                                                                               |
| `setValue(ref, value)`     | Fills in a field with `{ value }`, `{ checked }` or `{ selectedValues }`, running the form's checks and scripts. Resolves `{ field, status }`. [Fill in a field](#fill-in-a-field) |
| `setValues(entries)`       | Fills in several fields in order, each `{ ref, value }`; one that fails doesn't stop the rest. Resolves `{ applied, skipped, failed }`.        |
| `importValues(values)`     | Fills in fields by full name from a plain object. Resolves `{ applied, skipped, failed }`. [Move form data in and out](#move-form-data-in-and-out) |
| `exportValues()`           | Every value, keyed by full name, as a plain object                                                                                             |
| `export(format?)`          | The form data as XFDF, or FDF with `'fdf'`. Resolves `{ format, bytes }`.                                                                      |
| `import(bytes)`            | Fills in the fields from FDF or XFDF bytes, telling the format by itself. Resolves `{ applied, skipped }`.                                     |
| `reset(refs?)`             | Puts back each field's default, for the whole form or the fields you pass. Resolves `{ fields }`, the fields it changed. [Reset the form](#reset-the-form) |
| `validate()`               | Checks the required fields. Returns `{ valid, missing }`, the empty ones in page order. [Check required fields](#check-required-fields)        |
| `activateWidget(widget)`   | Does what a click on a field box does, such as running a button's action                                                                       |
| `getSnapshot()`            | Everything at once, as the engine's `list()` returns it: `fields`, `widgets`, `formKind`, `needsAppearances` and `calculationOrder`             |
| `refresh()`                | Reads the whole form again, and <Fw only={['react', 'vue', 'svelte']}>`onResynced`</Fw><Fw only="angular">`resynced$`</Fw> fires. You rarely need it: the plugin follows every change, whoever made it.                      |
| `canRead()`, `canFill()`   | Whether reading the form, and filling it in, are allowed. [Permissions](#permissions)                                                         |
| `getSettings()`, `updateSettings(changes)`, `resetSettings()` | Reads the settings, changes them while the app runs, or goes back to what you registered. In a component, use `useFormSettings()`. [Settings](#settings) |

Every method that returns a promise also takes a `signal` in its options, to cancel it.

| Field           | What it is                                                                                      | Read once                                            |

## Settings

Set them when you register the plugin, and change them while the app runs with
`form.updateSettings({ … })`; `form.resetSettings()` goes back to what you registered, and
`useFormSettings()` gives you the current settings.

| Setting             | What it does                                                               | Default                      | From CSS                       |
| :------------------ | :------------------------------------------------------------------------- | :--------------------------- | :----------------------------- |
| `validation`        | Run the form's own checks (`'scripts'`), or accept every value (`'none'`)  | `'scripts'`                  | —                              |
| `focus.color`       | The ring around the field being filled in                                  | the viewer's accent          | `--epdf-form-focus`            |
| `fields.border`     | The edge of a field that has no border of its own                          | the viewer's accent at 55%   | `--epdf-form-field-border`     |
| `fields.background` | Inside a field that has no background of its own                           | `'rgb(255 255 255 / 0.92)'`    | `--epdf-form-field-background` |
| `fields.color`      | The check mark and text of a field that has no color of its own            | `'#1f2a44'`                    | `--epdf-form-field-color`      |

Scripts need JavaScript on in the actions plugin; without it, `'scripts'` accepts every value too.

The colors are what the viewer draws around fields; a field's own colors are saved in the PDF (see
[Building forms](forms/building)). A CSS variable wins over the setting: see
[Colors & theming](ui/theming).

## Permissions

| Permission       | What it allows            | Check              |
| :--------------- | :------------------------ | :----------------- |
| `doc.forms.read` | Reading the form          | `form.canRead()`   |
| `doc.forms.fill` | Filling it in             | `form.canFill()`   |

Without `doc.forms.fill`, the fields show their values but can't be changed.

## Good to know

### Forms and annotations

A field's widgets are the form's: the annotation plugin never lists them. With the
[annotation plugin](annotations) registered, the `<FormLayer>` and the annotation layer share the page: fields stay fillable with the
`pointer` tool, and become movable boxes in [design mode](forms/building).

### Keyboard

Tab moves to the next field in the page's order. In a text box, Enter confirms and Escape puts back
the value it had.

### XFA forms

Some PDFs also carry a form in the older XFA format. The viewer works with the document's regular
fields and never runs XFA; see [Forms](/docs/engine/forms#xfa-forms).

### Signed documents

A signature can lock the whole form, or some fields. Locked fields show their values and can't be
changed; see [Signatures](forms/signatures).
