# Documents

<Engine local>

Give the viewer a document with `src`: a URL, a `File`, or bytes.

```js
{ src: '/reports/2026-q3.pdf' }
```

A relative URL is relative to your page. A URL on another site needs CORS headers that allow
yours, like any `fetch`.

## Open the file someone picks

</Engine>

<Engine cloud>

Give the viewer a document with `src`. Every document lives on CloudPDF, and `src` says which one
and who opens it:

| `src` | What it is |
| :-- | :-- |
| `{ token }` | A token your backend creates for the user and one document. It says who they are and what they may do. |
| `{ id }` | A document by its id, when the engine's own token allows it (`engine: { token }`) |
| `{ grant }` | A grant from the CloudPDF dashboard (`grt_…`): public access, which needs no backend |

```js
{ src: { token: () => fetchDocumentToken('contract-42') } }
```

A token is a string, or a function that gives a fresh one when the old one runs out. The pages come
from CloudPDF, so there's no file to serve and no CORS to set up; a grant opens only on the
websites it allows. [Authentication](/docs/engine/authentication) has what a token carries.

## Open the document someone picks

</Engine>

`src` follows its prop: give it another document, and the viewer opens that one in its place.

<Snippet name="viewer/documents/pick-file" />

<Engine local>

People can also open files themselves: drop a PDF on the viewer, or use **Open** in the document
menu. Both open it as a new tab.

</Engine>

<Engine cloud>

On CloudPDF, every document comes from your server, so the viewer has no **Open** and takes no
dropped files.

</Engine>

## Several documents

Give `documents` instead of `src` to open several at once. Each one gets a tab:

<Engine local>

```js
{
  documents: [
    { src: '/contract.pdf', name: 'Contract' },
    { src: '/appendix.pdf', name: 'Appendix A' },
    { src: '/scan.pdf', name: 'Signed scan', active: true },
  ],
}
```

| Field | What it is | Default |
| :-- | :-- | :-- |
| `src` | A URL, a `File`, or bytes | none |
| `name` | What its tab shows | the file's name |
| `password` | Its password, if it has one | none |
| `active` | Show this one first | the first document |

</Engine>

<Engine cloud>

```js
{
  documents: [
    { src: { token: contractToken }, name: 'Contract' },
    { src: { token: appendixToken }, name: 'Appendix A' },
    { src: { token: scanToken }, name: 'Signed scan', active: true },
  ],
}
```

| Field | What it is | Default |
| :-- | :-- | :-- |
| `src` | `{ token }`, `{ id }` or `{ grant }` | none |
| `name` | What its tab shows | `Document` and the start of its id |
| `password` | The PDF's password, if it has one | none |
| `active` | Show this one first | the first document |

</Engine>

The tabs show while more than one document is open. To show them always or never, set
`layout.tabs('always')` or `layout.tabs('never')` in your [layout](customize/layout).
`onDocumentChange` tells you which document is showing each time that changes, and `null` once none is.

## Passwords

A document with a password opens locked, and the viewer asks for it. When you know it, pass it
along and nobody is asked:

<Engine local>

```js
{ documents: [{ src: '/payroll.pdf', password: secret }] }
```

</Engine>

<Engine cloud>

```js
{ documents: [{ src: { token: payrollToken }, password: secret }] }
```

That's the PDF's own password. A grant's passphrase is another one: it goes with the grant,
`src: { grant, passphrase }`. Without it, the viewer asks for it in the document's tab.

A grant can also ask who the visitor is. The viewer asks in the document's tab before it
opens, or in a dialog when the visitor first changes something, as the grant says. When your page
already knows who the visitor is, give it as the viewer's `identity`:
`identity: { displayName, email }`. The grant takes the fields it asks, as if the visitor typed
them. See
[Authentication](/docs/engine/authentication#who-the-visitor-is) for what a grant can ask.

</Engine>

A wrong password asks again. A document that can't be opened at all shows why in its tab, with a
**Try again** button.

## Open and close documents from code

`viewer.documents` opens, closes and switches documents. It's the documents plugin, the same as
[in headless](/docs/headless/documents/opening):

<Engine local>

```js
const { document } = await viewer.documents.open(
  { kind: 'url', url: '/invoice-1042.pdf' },
  { name: 'Invoice 1042' },
);

viewer.documents.setActive(document.id);
viewer.documents.close(document.id);
```

</Engine>

<Engine cloud>

```js
const { document } = await viewer.documents.open(
  { kind: 'token', token: () => fetchDocumentToken('invoice-1042') },
  { name: 'Invoice 1042' },
);

viewer.documents.setActive(document.id);
viewer.documents.close(document.id);
```

`open()` takes a document as the engine names it: `{ kind: 'token' }`, `{ kind: 'id' }` or
`{ kind: 'grant' }`, as in [Authentication](/docs/engine/authentication).

</Engine>

`open()` resolves once the document is ready, and makes it the active one.

## Download and print

The document menu has **Download** and **Print**, and `Ctrl`/`Cmd`+`S` and `Ctrl`/`Cmd`+`P` work
while the viewer has focus. A download includes every annotation, form value and signature.

**Print** opens a dialog: every page, the current page or pages such as `1-3, 5`, and whether
annotations print. Nothing is made while the user chooses: its **Print** button prepares those
pages, shows how far it is, and opens the browser's print dialog when they're ready. Safari prints
only from a tap, so there the dialog says the pages are ready and prints from the next tap on
**Print**. Pages print as the PDF says they print: an annotation or a form field that is
set not to print stays off the paper. On a desktop browser with its own PDF viewer, a document that
allows high-quality printing and downloading prints as a PDF, with sharp text and lines. Everywhere
else the pages print as pictures, at 300 DPI, or at 150 DPI when the document allows only
low-resolution printing; the dialog says which.

When the scope doesn't allow printing, or you [turn it off](features/turning-off), **Print** isn't
there, and `Ctrl`/`Cmd`+`P` says so instead of printing the web page.

To run them from your own button, use the commands `document:download` and `document:print`, or
call them from code. The command opens the dialog; `documents.print()` prints every page without
it:

```js
viewer.commands.execute('document:print');
await viewer.documents.print();
```

## Save to your server

`viewer.documents.download()` gives you the PDF with every change, as bytes, without a download
dialog. Make it a button of your own:

```js
{
  commands: [
    {
      id: 'acme:save',
      label: 'Save',
      icon: 'save',
      shortcut: 'Mod+S',
      run: async ({ viewer, documentId }) => {
        const bytes = await viewer.documents.download(documentId);
        await fetch(`/api/documents/${documentId}`, { method: 'PUT', body: bytes });
      },
    },
  ],
  layout: (layout) => layout.replace('document:download', 'acme:save'),
}
```

`Mod+S` now saves to your server instead of downloading, because a command of yours wins over a
built-in one with the same shortcut.

<Engine local>

<CloudPdfCallout

With CloudPDF, every annotation, comment and form value is stored on your server the moment it's
made, and everyone who has the document open sees it. There's no file to upload and nothing to
lose when the tab closes.

</CloudPdfCallout>

</Engine>

## Warn before changes are lost

When someone closes a tab or leaves the page with unsaved changes, the viewer asks first. Unsaved
means changed since it opened or since the last download. `viewer.documents.get().hasUnsavedChanges`
tells you the same, and `onUnsavedChangesChanged` fires when it changes:

```js
viewer.documents.onUnsavedChangesChanged(({ documentId, hasUnsavedChanges }) => {
  saveButton.disabled = !hasUnsavedChanges;
});
```

## Good to know

### Big files

<Engine local>

The local engine needs the whole file before the first page shows, so a large scan takes as long
as its download. The toolbar is there at once; only the pages wait.

</Engine>

<Engine cloud>

CloudPDF renders each page on the server and sends it as an image, so the first page shows at
once, without the browser downloading the whole PDF.

</Engine>

### Where the bytes go

<Engine local>

With the local engine, a document never leaves the browser: no upload, no server. Each document
runs in the engine's worker, so a heavy page doesn't freeze your app.

</Engine>

<Engine cloud>

The file stays on CloudPDF. The browser gets the pages as images, and only what the token allows:
a user who may not download never receives the file, and one who may not copy never receives the
text.

</Engine>
