# Signatures

A digital signature has two parts: the **mark**, what people see in the signature field, such as a
drawn signature; and the **key**, which seals the document so any later change shows. The signature
plugin signs with both, checks the signatures a document already has, and warns before an edit would
break one.

Register `signaturePlugin()` next to `formPlugin()` and `stampPlugin()`, with the key to sign with:

## Sign a field

```ts
const { version } = await signature.sign({
  field: toFieldRef('approval'),
  mark: { assetId },
  signer: { reason: 'Approved', location: 'Amsterdam' },
});
```

The mark becomes what the field shows, the key seals the document, and the signed document is saved
as a new version. If anything fails along the way, nothing is left half-signed.

A mark is a stamp from a person's signature library, or image bytes you bring:

```ts
{ assetId } // a stamp, drawn, typed or uploaded; see "A person's signatures" below
{ source: pngBytes } // a PNG, a JPEG, or a one-page PDF
```

## Let people click to sign

People can also arm their signature and click where it goes, as in Preview. With the stamp plugin, arm
a mark from a signature library:

- **over an empty signature field**, the click signs it;
- **over a signed field**, nothing happens;
- **anywhere else**, the mark is placed as a stamp.

`placeMark()` does the same from code:

```ts
await signature.placeMark({ assetId }, { field: toFieldRef('approval') }); // signs the field
await signature.placeMark({ assetId }, { page: page.ref, center: { x: 120, y: 90 } }); // a stamp
```

What happens in a field depends on `mode`: `'sign'` signs it, `'visual'` only draws the mark in,
and `'ask'` asks your UI first through <Fw only={['react', 'vue', 'svelte']}>`onSignRequested`</Fw><Fw only="angular">`signRequested$`</Fw>, so you can show your own sign dialog.

## Fill a field without signing

Sometimes a signature only needs to look signed, such as for a form that gets printed. Draw the mark
into the field without sealing anything:

```ts
await signature.fillField(toFieldRef('approval'), { source: pngBytes });
await signature.clearField(toFieldRef('approval'));
```

A signed field can't be filled or cleared: what it shows is part of what was signed.

## The key

The engine never holds a key. You give the plugin a **signer**, which does the signing.
`@embedpdf/react/signature` has one for each case:

```ts
// Your own key and certificate chain
webCryptoSigner({ privateKey, certificateChain: [leaf, issuer] });

// Your signing service or hardware module: only the document's fingerprint leaves the browser
remoteSigner({ sign: ({ digest, algorithm, subFilter }) => api.sign(digest, algorithm, subFilter) });

// A key per person, created in the browser and kept there, never readable
personalSigner({ subject: 'Ada Lovelace', store: indexedDbKeyStore('my-app-keys') });

// For tests and demos
createTestSigner({ commonName: 'Demo' });
```

A personal signer works like signing in Preview, with real cryptography: a reader who trusts that
person's certificate sees a valid signature, and everyone else sees "validity unknown", the honest
answer for a key the person made themselves. For signatures everyone can check, sign with a
certificate from a trusted provider, through `webCryptoSigner` or `remoteSigner`.

### Signing in two steps

When the key signs somewhere else, such as on a phone or in a signing service that asks for approval,
split the signing in two:

```ts
const { signingId, digest } = await signature.prepareSignature({ field, mark: { assetId } });
const cms = await myService.sign(digest); // may take minutes
await signature.completeSignature(signingId, cms);
```

While a signature is prepared, the document can't be changed, so nothing can slip in between.
`signature.cancelPending()` gives up.

`completeSignature()` checks what the key returned before it seals anything. When it fails,
nothing is written and the signature stays prepared:

- **The timestamp authority didn't answer** (`Network`): call `completeSignature()` again with the
  same `cms`. The key doesn't sign twice.
- **The `cms` was refused** (`SignatureRefused`), for example because it signs another
  fingerprint: it will be refused again. Call `cancelPending()` and start over.

### A timestamp with every signature

A signature says when it was made, by the signer's own clock. A timestamp authority vouches for
that time, so a reader doesn't have to take the signer's word for it, and the signature can still
be checked after the signer's certificate expires. Set one when you register the plugin, and every
signature it seals carries a timestamp:

```ts
signaturePlugin({
  signingKey,
  timestampAuthority: httpTimestampAuthority({
    url: '/api/timestamp',
  }),
});
```

`httpTimestampAuthority()` comes from the same place as the signers. Most authorities can't be
called from a web page, so `url` is a route of your own that passes the request on;
[Reach the authority from a browser](/docs/engine/forms/signatures#reach-the-authority-from-a-browser)
has one.

- **A timestamp is never skipped.** When the authority can't be reached or its answer doesn't
  check out, the signing fails and nothing is signed.
- **One signature without a timestamp:** pass `timestampAuthority: null` to that `sign()` or
  `prepareSignature()`. Pass another authority to use that one instead.
- **In two steps**, `prepareSignature()` reserves room for the timestamp and
  `completeSignature()` adds it.
- **With `trust` set, the authority must be one you trust.** The plugin won't seal a timestamp
  from an authority your `trust` doesn't cover, so a wrong address fails at the first signature
  and not at the first reader. List the authority's root under `timestampAnchors`:

```ts
signaturePlugin({
  signingKey,
  timestampAuthority,
  trust: {
    anchors: async () => [companyRoot],
    timestampAnchors: async () => [authorityRoot],
  },
});
```

### Keep a signature checkable for years

A timestamp proves when a signature was made. To check the signature years later, a reader also
has to know that the signer's certificate had not been withdrawn by then, and its issuer may no
longer answer that question. Set `revocation`, and every signature the plugin seals gets those
answers right after, stored in the file. Acrobat shows such a signature as "LTV enabled":

```ts
signaturePlugin({
  signingKey,
  timestampAuthority: httpTimestampAuthority({ url: '/api/timestamp' }),
  revocation: httpRevocationSource({ url: '/api/revocation' }),
  documentTimestamp: true,
  trust,
});
```

`httpRevocationSource()` comes from the same place as the signers. A web page can't call a
certificate's issuer, so `url` is a route of your own that passes the question on;
[Reach the issuers from a browser](/docs/engine/forms/signatures#reach-the-issuers-from-a-browser)
has one.

- **It needs `trust` and a timestamp.** The answers kept are the ones for the certificates
  between the signer and a certificate you trust, at the time the timestamp proves.
- **`documentTimestamp: true` adds a document timestamp after the answers**, from
  `timestampAuthority`. It proves the answers were in the file by then, which a strict validator
  asks for.
- **The signature is sealed first.** The answers go into the file after the signature, so a
  failure there can't undo it: `sign()` still resolves, and its result says what happened.

```ts
const result = await signature.sign({ field, mark });

result.validationInfo;
// { added: { certificates: 3, ocspResponses: 2, crls: 0 },
//   documentTimestamp: { kind: 'fqn', name: 'Timestamp1' } }

if (result.validationInfoError) {
  // Signed, but the file doesn't hold the answers yet. Try again later:
  await signature.addValidationInfo(result.signature.field);
}
```

- **Only the signature just made is covered.** Other people's signatures may name issuers that
  no longer answer. `signature.addValidationInfo()` with no field covers every signature, and
  rejects when one can't be covered.
- **It takes the `doc.sign` permission.** Someone who may only sign their own group's fields
  signs without it, and `result.validationInfo` is `null`. Whoever finishes the document then
  calls `signature.addValidationInfo()` once, for everyone.
- **`completeSignature()` and `placeMark()` do the same** as `sign()`.

## Check the signatures

<Snippet name="forms/signature-list" />

A verdict's `summary` is:

| Summary             | Means                                                               |
| :------------------ | :------------------------------------------------------------------ |
| `'valid'`           | Nothing changed since it was signed, and you trust the signer       |
| `'valid-untrusted'` | Nothing changed, but the signer's certificate isn't one you trust   |
| `'invalid'`         | The document changed in a way the signature doesn't allow           |
| `'indeterminate'`   | It couldn't be checked, for example because a certificate is missing |

The plugin checks the signatures when the document opens, and again after every change. For a
detailed report of what changed since a signature, rule by rule, use `signature.analyzeChanges()`.

`'valid'` means the signer's certificate is within its dates and leads to one you trust.
Whether it was withdrawn is in `verdict.revocation`: `'good'`, `'revoked'` or `'unknown'`, read
from the answers the file holds. Proof of a withdrawal makes the summary `'invalid'`, and
`'unknown'` never changes it. The plugin asks nobody when it checks, so opening a document
doesn't tell a certificate authority who is reading it.

### Whether it can be checked for years

`verdict.longTerm` says whether the file holds everything a reader needs, with no network:

```ts
const { longTerm } = verdict;

longTerm.enabled; // true: what Acrobat calls "LTV enabled"
longTerm.expiresAt; // the day that proof runs out, or null
longTerm.missing; // what stands in the way: [{ certificate, reason }]
```

For a signature that isn't there yet, offer to add what is missing:

```ts
if (!verdict.longTerm.enabled && signature.canAddValidationInfo()) {
  await signature.addValidationInfo(verdict.signature.field);
}
```

`addValidationInfo()` asks through the `revocation` setting, stores the answers, and adds a
document timestamp when `documentTimestamp` is set and the answers aren't covered by one yet. It
rejects, and stores nothing, when an answer is missing: `error.details.reason` says why
(`'no-timestamp'`, `'untrusted'`, `'no-answer'` or `'revoked'`), and `error.details.source` names
an address that didn't answer. [Long-term validation](/docs/engine/forms/signatures#long-term-validation)
has every field.

### When it was signed

A signature with a timestamp has a second verdict, in `verdict.timestamp`: `null` when the
signature has none. Show the time the authority vouches for when you trust it, and the signer's
own claim otherwise:

```ts
const stamp = verdict.timestamp;
const when =
  stamp?.summary === 'valid'
    ? `${stamp.stampedAt}, confirmed by ${stamp.authorityName}`
    : `${verdict.signature.signer.signedAt}, the signer's clock`;
```

A timestamp's verdict never changes the signature's `summary`: a valid signature with a broken
timestamp is still valid.

Each certificate is judged at the signature's trusted timestamp, when it has one, so a
signature whose signer's certificate has expired since still reads `'valid'`. To judge every
certificate as of now:

```ts
await signature.validate({
  validationTime: { kind: 'now' },
});
```

[The timestamp](/docs/engine/forms/signatures#the-timestamp) has every field of the verdict, and
what this option does and doesn't check.

## Warn before an edit breaks a signature

After an approval signature, filling in the form, commenting and adding more signatures keep it
valid, as in Acrobat. Other changes break it once the file is saved, such as adding a form field. The
plugin warns you the moment a change would do that, as Acrobat does:

<Snippet name="forms/break-warning" />

`signature.getProtection()` tells you what the document's signatures allow, before anyone tries. A
signer who wants to rule out more, such as comments, certifies the document to allow form filling
only: the engine then refuses those changes instead of warning about them.

## A person's signatures

A person's signature and initials are stamps, in a library of kind `'signatures'`, drawn, typed or
uploaded with the [stamp plugin](../annotations/stamps):

```ts
const { library } = await stamp.createLibrary('Ada Lovelace', { kind: 'signatures' });
await stamp.createAsset({ libraryId: library.id, name: 'signature', label: 'Signature', mark: { kind: 'ink', strokes } });
await stamp.createAsset({
  libraryId: library.id,
  name: 'initials',
  label: 'Initials',
  mark: { kind: 'text', text: 'AL', fontFamily: 'times-italic' },
});
```

<Fw only={['react', 'vue', 'svelte']}>`useSignerRows()`</Fw><Fw only="angular">`signature.signerRows()`</Fw> lists each person with their signature and initials, for a picker. The library is
a normal PDF, so Acrobat can open it too.

## "Sign here" in a form

With the [form layer](../forms), an empty signature field can be clicked. The layer draws no "sign
here" text in it: the field is a button with nothing in it, named after the field for screen readers.
Clicking it makes the field the **target**: the next mark the person picks goes there. A signed field,
clicked, asks your UI to show its details:

```ts
signature.setTarget(toFieldRef('approval')); // the next mark goes here; null clears
```

| Event                   | Fires when                                     | Show                     |
| :---------------------- | :--------------------------------------------- | :----------------------- |
| <Fw only={['react', 'vue', 'svelte']}>`onTargetChanged`</Fw><Fw only="angular">`targetChanged$`</Fw> | A field became the target                      | your signatures panel    |
| <Fw only={['react', 'vue', 'svelte']}>`onSignRequested`</Fw><Fw only="angular">`signRequested$`</Fw> | In `'ask'` mode, a mark was dropped on a field | your sign dialog         |
| <Fw only={['react', 'vue', 'svelte']}>`onInspectionRequested`</Fw><Fw only="angular">`inspectionRequested$`</Fw> | A signed field was clicked                     | the signature's details  |

## Methods

Everything `useSignature()` gives you.

| Method                                                    | What it does                                                                                                                              |
| :-------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------- |
| `sign({ field, mark })`                                   | Signs a field: the mark becomes what it shows, and the key seals the document. Also takes `signer`, a per-call `signingKey` and `timestampAuthority`, `certify` and `lock`, and resolves `{ signature, version, protection, validationInfo, validationInfoError }`. [Sign a field](#sign-a-field) |
| `placeMark(mark, { field })`, `placeMark(mark, { page, center })` | Does what a click with an armed mark does: in a field, signs, fills or asks, by `mode`; anywhere else, places a stamp. Resolves what it did as `kind`: `'signed'`, `'filled'`, `'requested'` or `'placed'`. [Let people click to sign](#let-people-click-to-sign) |
| `fillField(field, mark)`, `clearField(field)`             | Draws a mark into a field without signing, or takes it out again. Refused on a signed field. [Fill a field without signing](#fill-a-field-without-signing) |
| `prepareSignature({ field, mark })`, `completeSignature(signingId, cms)` | Signs in two steps: the first resolves `{ signingId, digest }` for your key to sign, the second checks what the key returned, adds the timestamp when an authority is set, and seals the document. [Signing in two steps](#signing-in-two-steps) |
| `cancelPending()`                                         | Gives up a signature prepared in two steps, so the document can be changed again                                                          |
| `validate({ until?, validationTime? })`                   | Checks every signature again and resolves the verdicts. `until: 'persisted'` checks the file as it was opened; `validationTime` judges each signature at its timestamp. [Which bytes are checked](#which-bytes-are-checked), [When it was signed](#when-it-was-signed) |
| `validateField(field)`                                    | Checks one signed field and resolves its verdict                                                                                          |
| `addValidationInfo(field?)`                               | Asks whether a signed field's certificates were good at its timestamp, stores the answers in the file, and adds a document timestamp when `documentTimestamp` is set. Without `field`, for every signature. Resolves `{ added, documentTimestamp }`. [Whether it can be checked for years](#whether-it-can-be-checked-for-years) |
| `getVerdict(field)`, `listVerdicts()`                     | One signed field's verdict from the last check, or every verdict; `null` before the first check. [Check the signatures](#check-the-signatures) |
| `getSignature(field)`                                     | One signature field's facts, signed or not, such as `fieldName`, `signed` and `signer`, or `null`                                         |
| `listUnsignedFields()`                                    | The signature fields still to sign, in document order                                                                                     |
| `analyzeChanges({ since })`                               | What changed after a signature (`{ signatureIndex }`) or a version of the file (`{ revisionIndex }`), rule by rule                         |
| `readRevision(field)`, `readRevision({ revisionIndex })`  | The exact bytes of the file version a signature covers. [The signed bytes](#the-signed-bytes)                                             |
| `setTarget(field)`                                        | Makes a field the target, where the next mark the person picks goes; `null` clears. ["Sign here" in a form](#sign-here-in-a-form)          |
| `requestInspection(field)`                                | Asks your UI to show a signed field's details, as clicking it does: <Fw only={['react', 'vue', 'svelte']}>`onInspectionRequested`</Fw><Fw only="angular">`inspectionRequested$`</Fw> fires                                         |
| `getMode()`                                               | The mode in effect: the `mode` setting, or its default. [Settings](#settings)                                                            |
| `getSnapshot()`                                           | Everything at once, as the engine reads it: every signature field, signed or not, the file's versions, and `protection`                   |
| `refresh()`                                               | Reads the signatures again. You rarely need it: the plugin reads and checks them again after every change.                                |
| `canSign(field)`, `canCertify()`, `canFill(field)`, `canReadRevision()`, `canAddValidationInfo()` | Whether signing a field, certifying, drawing a mark into a field without signing, reading the signed bytes, and adding validation data are allowed. [Permissions](#permissions) |
| `getSettings()`, `updateSettings(changes)`, `resetSettings()` | Reads the settings, changes them while the app runs, or goes back to what you registered. In a component, use `useSignatureSettings()`. [Settings](#settings) |

`field` is a field's ref, such as `toFieldRef('approval')`; the methods that only read also take the
ref of the field's box. Every method that returns a promise also takes a `signal` in its options, to
cancel it.

## Settings

Set them when you register the plugin, and change them while the app runs with
`signature.updateSettings({ … })`; `signature.resetSettings()` goes back to what you registered, and
`useSignatureSettings()` gives you the current settings.

| Setting        | What it does                                                           | Default                         |
| :------------- | :--------------------------------------------------------------------- | :------------------------------ |
| `signingKey`   | The signer, or a function that returns one when someone signs          | none                            |
| `timestampAuthority` | The timestamp authority: every signature the plugin seals carries its timestamp | none           |
| `revocation`   | Where revocation answers come from: every signature the plugin seals gets its validation data right after. Needs `trust` | none |
| `documentTimestamp` | Add a document timestamp after the validation data. Needs `timestampAuthority` | `false`           |
| `mode`         | What a mark does in a field: `'sign'`, `'visual'` or `'ask'`           | `'sign'` with a key, else `'visual'` |
| `trust`        | The certificates you trust: for checking signatures, and for the timestamps you seal | none              |
| `allowCertify` | Let a first signature be a certification, which sets what stays allowed | `false`                        |

## Permissions

| Permission         | What it allows                              | Check                         |
| :----------------- | :------------------------------------------ | :---------------------------- |
| `doc.sign`         | Signing                                     | `signature.canSign(field)`    |
| `doc.sign`         | Adding validation data and a document timestamp | `signature.canAddValidationInfo()` |
| `doc.sign.certify` | Signing a certification                     | `signature.canCertify()`      |
| `doc.sign`         | Drawing a mark into a field without signing | `signature.canFill(field)`    |
| `doc.download`     | Reading the exact bytes a signature covers  | `signature.canReadRevision()` |

A mark in a signature field is its signer's to place, so drawing one takes what signing takes. A user
with a `fields:sign` permission for one group signs that group's fields only, and draws marks only into
them, so the checks take the field. See [Signers and groups](/docs/engine/forms/groups). On a
signed document, the engine also refuses what its signatures forbid.

## Good to know

### Which bytes are checked

The plugin checks the document as it is in the viewer, with changes that haven't been downloaded yet,
so the verdict is the one the downloaded file will get. `validate({ until: 'persisted' })` checks the
file as it was opened.

### The signed bytes

`signature.readRevision({ revisionIndex })` gives you the exact version of the file a signature
covers, for an audit trail.
