# Engine & handles

The engine exposes three layers of objects: the **engine** itself, a
**document handle** for each open document, and a **page handle** for per-page
work. Each layer narrows the scope of what you operate on.

## The engine

<Engine cloud>
`cloudEngine(options)` returns an object implementing the `Engine` interface:
</Engine>

<Engine local>
`localEngine()` returns an object implementing the `Engine` interface. Its
WebAssembly binary and worker ship inside your build — nothing is fetched from
a CDN; [Self-hosting & air-gapped deployments](/docs/viewer/self-hosting) lists
every option (`assetsUrl`, `wasmUrl`, `wasmBinary`, `worker`) and the portable
entry for toolchains that cannot emit the asset:
</Engine>

```ts
interface Engine {
  open(input: OpenInput, options?: OpenOptions): AbortablePromise<DocumentHandle>;
  destroy(): AbortablePromise<void>;
}
```

`open()` is the only entry point.

<Engine cloud>
The cloud engine accepts three input kinds — `{ kind: 'token' }`,
`{ kind: 'id' }`, and `{ kind: 'share' }` (see
[Authentication](/docs/engine/getting-started/authentication)).
</Engine>

<Engine local>
The local engine accepts `{ kind: 'bytes' }` (and `{ kind: 'layerBytes' }`
for layer documents) — you hand it the PDF bytes and a stable id (see
[Getting started](/docs/engine/getting-started)).
</Engine>

Call `destroy()` when your app is shutting the engine down; existing handles
should be `close()`d first.

<Callout type="info">
  One engine can hold many open documents at once. When you open by token, each
  handle carries its own per-document bearer, so a single engine can serve
  several independently-authorized documents concurrently.
</Callout>

## The document handle

`open()` resolves to a `DocumentHandle` — your entry point to everything about
one open document:

```ts
interface DocumentHandle {
  readonly id: string;
  readonly capabilities: DocumentCapabilities;
  readonly security: DocumentSecurityService;
  readonly metadata: MetadataService;
  readonly annotations: DocumentAnnotationsService;
  readonly pages: DocumentPagesService;
  readonly render: DocumentRenderService;

  page(ref: PageRef): PageHandle;
  download(opts?: { mode?: PdfSaveMode }): AbortablePromise<Uint8Array>;
  close(): AbortablePromise<void>;
}
```

- `metadata`, `annotations`, `pages`, and `security` are **document-scoped
  services** (covered in their own pages).
- `render` carries the document's render *policy* — not pixels; per-page
  rendering stays on `page(ref).render`. See
  [Render policy](/docs/engine/core-concepts/pages-and-rendering#render-policy).
- `page(ref)` returns a page handle (below).
- `download()` returns the full PDF bytes — see [Downloading](/docs/engine/core-concepts/downloading).
- `close()` releases the handle. It's idempotent and safe to call more than
  once.

### Capabilities

`capabilities` advertises engine-specific behavior so portable code can adapt:

```ts
interface DocumentCapabilities {
  readonly weakAnnotationEditSessions: 'not-needed' | 'required';
  readonly pageEditSessions: 'unsupported' | 'supported';
}
```

On the cloud engine, `weakAnnotationEditSessions` is `'required'` (index-based
annotation edits need an active edit session) and `pageEditSessions` is
`'unsupported'`.

## The page handle

`doc.page(ref)` returns a `PageHandle` keyed on the page's **identity**, never
its display index — so the handle stays valid across page reorders.

A page is addressed by a `PageRef` — `{ kind: 'objectNumber', pageObjectNumber }`,
the page's indirect object number. Every `PageLayout.ref` carries one, and it
survives reorder, rotate and every edit: a deleted page's number is retired,
never recycled. Anything that points at a page carries the same ref as `page`
(`annotation.ref.page`, an event's `page`), so you never build an address by
hand; `toPageRef(n)` exists for a bare number.

<Engine cloud>
On the wire the same address is the `:pageKey` path segment — `/pages/obj:12/…`
— mirroring `annotKey` and `fieldKey`.
</Engine>

```ts
interface PageHandle {
  readonly ref: PageRef; // the address the handle was minted with
  readonly pageIndex: number; // advisory display index at mint time
  readonly annotations: PageAnnotationsService;
  readonly text: PageTextService;
  readonly geometry: PageGeometryService;
  readonly render: PageRenderService;
}
```

`page()` is synchronous — page records are already known to the handle. To
discover page refs, call `doc.pages.list()`:

```ts
const { pageCount, pages } = await doc.pages.list();
const page = doc.page(pages[0].ref);
```

<Callout type="warn">
  Treat <code>pageIndex</code> as advisory metadata. It reflects display order
  at the time the handle was minted; the durable key is always
  <code>ref</code>.
</Callout>

## Lifecycle at a glance

<Engine cloud>
```ts
const engine = cloudEngine({ baseUrl });

const doc = await engine.open({ kind: 'id', id: 'doc_123' }); // open
const page = doc.page((await doc.pages.list()).pages[0].ref); // work
await page.render.image();

await doc.close();    // release the document
await engine.destroy(); // tear down the engine
```
</Engine>

<Engine local>
```ts
const engine = localEngine();

const doc = await engine.open({ kind: 'bytes', id: 'doc_123', bytes }); // open
const page = doc.page((await doc.pages.list()).pages[0].ref); // work
await page.render.image();

await doc.close();    // release the document
await engine.destroy(); // tear down the engine
```
</Engine>
